## 원인과 우선순위

1. 가장 강한 근거: TownLandscape.wrap이 건물과 모든 소품의 frustumCulled를 false로 지정한다. 화면 밖 모델도 제출되어 수천 번의 호출과 수백만 삼각형 처리가 발생한다. 동일 장면의 진단 비교에서 렌더 호출 부하가 크게 줄었다. 반복 나무는 clone(true)로 생성되어 InstancedMesh로 묶이지 않는다.
2. 추가 CPU 비용: DialogueOcclusion.update는 대화 여부와 관계없이 매 프레임 실행한다. 전체 scene.updateMatrixWorld(true), 최대 두 배우×여섯 광선, 후보 모델 하위 실제 메시 raycast를 수행한다. 현행 호출에서 측정 가능한 비용과 순간 지연이 관찰됐다. 이 검사만 중지해도 주 렌더 병목은 남는다.
3. 고해상도 증폭: TownModelScene의 DPR 상한은 2이며 antialias가 켜져 있다. DPR 2는 DPR 1 대비 픽셀 수 4배다. 현재 측정은 DPR 1이므로 고해상도 영향은 별도 실측하지 않았다.
4. 특정 순간 후보: TownMusic.decodeTownWav는 긴 WAV를 메인 스레드에서 동기 반복문으로 변환한다. 최초 음악 시작·새 시간대 음악 로드 순간의 멈춤 후보이며 지속적인 렌더 병목과 구분한다. 이번 측정은 음악 사용자 입력을 활성화하지 않아 음악 지연을 검증한 것은 아니다.

최적화는 적용하지 않았다. 원시 측정은 profile.json, 재현 스크립트는 profile.cjs다.
