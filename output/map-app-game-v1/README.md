# 지도 앱 2D UI·실제 내 위치 게임 적용 v1

사용자 확정 시안을 HTML/CSS/SVG의 phone/map/로 게임에 연결했다. 현재 TOWN_MODEL_BUILDINGS9개, villagePathRoutes, TOWN_PLAZA를 직접 읽으며 현행 전체 월드3700×2600을 지도에 투영한다. 숲·길·건물은 지도용 평면 픽토그램으로 표현하고 게임3D 에셋/안내소 벽 지도는 변경하지 않았다.

## 실제 위치·조작

일반 모드는 app.townStage.playerController, 전시는 scenes.townStage.playerController의 charPosX/Y를250ms마다 읽는다. 위치를 알 수 없으면 확인 중으로 표시하며 예시 도착 위치를 대입하지 않는다. 실내는 로컬 방 좌표를 마을 좌표로 섞지 않고 실제 활성 방의 건물 위치와 실내 라벨을 표시한다. 지도는 실내 평면도가 아닌 마을 시설 지도다.

시설 이름 검색·전체/생활/금융/상점 필터·시설 클릭/Enter/Space·장소 안내·목적지 핀·1~2.5배 확대/축소·드래그 이동·내 위치로 재중심을 제공한다. 주변 시설3곳은 현재 좌표 기준 직선 거리 순이다. 이동 시간이나 장애물을 피한 보행 경로를 계산하지 않는다. 목적지는 normal/exhibition 별 localStorage에 저장하며 자동 이동·순간 이동을 실행하지 않는다.

## 적용·검증

후속 업적 앱까지 함께 반영한13개 파일은 synced-files.txt를 따른다. 웹/기존 실행본 resources/web의 동일 해시를 확인했다. 설치 프로그램은 재빌드하지 않았다.

phoneMap.test.mjs:2개 통과(현행9개/전체월드 투영/야외 실시간 좌표/실내 구분/위치 불명).
check-phone-map.cjs: 웹/기존 실행본 실제 게임의 플레이어 컨트롤러 좌표와 SVG 마커가 일치하고 좌표 변경에 반응함을 확인했다. 전시·실내 건물 표시·검색/필터/선택·목적지 재진입 유지·확대/재중심·모바일·홈 복귀·페이지 오류0건 확인. 최종 실행본 검사는 SVG 시설 Enter 선택도 확인했다. 검증 중 좌표/활성 방을 격리 브라우저에서 조정했으며 실제 전체 이동 동선을 재플레이하지 않았다. 사용자 최종 시각/플레이 검수는 별도다.

공통 PhoneHome에 앱별 키 캡처를 추가해 모달 상태에서도 SVG 시설을 키보드로 선택한다. 앱 종료 시 해제한다. 공통 홈 복귀 시 이전 앱 DOM을 비워 숨겨진 stock-body에 :has가 매칭되어 큰 프레임이 남던 문제를 해결했다. 지도/업적 상세 진입 시 스크롤도 맨 위로 복원한다.
