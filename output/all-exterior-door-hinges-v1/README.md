# 나머지 건물 정면 문 경첩 개폐 — 2026-10-25

은행·가구점·도란 쉼터·증권사·서점·우체국의 정면 출입문에 경첩 중심 개폐를 적용했다. 안내소·집·잡화점의 앞선 수정은 유지한다. `ExteriorDoors.js`에서 실제 모델 변환을 포함한 건물 로컬 좌표로 축을 계산한다.

- 증권사: 기존 황동 경첩 핀 원점. 장식용 `Hinge_Left/Right` 그룹 원점 대신 실제 핀 중심을 사용한다. 현재 `Reference_Door_Leaf_*` 문짝·손잡이·고정부·홈 장식을 연결한다.
- 서점·우체국: 원점이 아닌 정점에 위치가 내장된 `Door_Hinge_Barrel`의 실제 중심. 유리·손잡이·경첩판·하단 장식을 함께 회전한다.
- 은행·가구점·쉼터: 원본에 핀이 없어 문짝 바깥쪽과 문틀 접점에 문짝당 황동 핀 2개를 런타임으로 추가하고 그 핀 중심을 축으로 사용한다. 원본 GLB는 변경하지 않는다.

양문은 서로 반대 방향으로 86.4도, 0.55초에 열리고 닫힌다. 창유리 구멍까지 포함한 검은 실내 가림을 유지하고 문틀·상부 채광창·건물은 고정한다. 문 부속품은 static batching/개별 정적 culling에서 제외한다. 초기 충돌과 지붕·모델 배치는 유지한다. 실내가 없는 건물에 실내나 경제 기능은 만들지 않는다. 우체통 수거문·직원용 옆문 등 보조 개구부는 이번 정면 출입문 범위가 아니다.

여섯 건물은 정면 가까이 가면 열리고 멀어지면 닫힌다. 140/180 거리의 여유 구간으로 경계에서 반복 개폐를 줄이며 출입 연출 중에는 근접 제어를 멈춘다. 은행 스토리 개폐도 같은 캐시와 축을 사용한다. 증권사 입장은 준비된 로비로 전환하기 전에 문 앞까지 걷기·개방·실제 문 통과를 수행한다. 전시에서 실외로부터 증권사에 갈 때 기존 모아 선행/플레이어 직접 추종 경로로 먼저 증권사 앞에 도착한다.

검증: 관련 Node 테스트 9개 통과(중간 개폐 방향 전환 시 이전 Promise 종료·핀 고정·문틀 고정·양문 방향 포함). `scratch/check-all-exterior-door-hinges.cjs`로 실제 GLB 6종을 위치 이동·100배 확대·회전시켜 확인했다. 두 쪽 회전·문틀 이동 0·핀 고정 최대 6.44e-13·원위치 복원 최대 5.09e-13·근접 개폐를 통과했다. `executable-checks.json`은 최종 실행본 코드의 결과다. `web-checks.json`은 손잡이 고정부/유리 가림 보완 전의 기하 검사 이력이며, 최종 웹/실행본 런타임 파일은 동일하다.

실제 전시 마을의 근접 개폐·6개 컨트롤러·동적 표시·194개 모델 로딩과 페이지 오류 0은 `web-game-checks.json`에 기록했다. 실제 마을 화면은 `game-*-open.png`, 카메라 추적과 가림을 고정한 문 확대 렌더는 `door-*-detail.png`다. 은행의 game-0 화면은 자동 카메라/가림 영향을 받으므로 은행 외관 검수에는 door-0-detail을 사용한다. `executable-game-checks.json`은 최종 실행본 리소스에서 같은 검사와 증권사 도보 통과·로비 전환(걷기 관측 250회)까지 통과한 결과다. 기존 실행본의 resources/web에도 변경한 6개 런타임 파일을 반영했다. 설치 프로그램 재빌드와 사용자 최종 시각·플레이 검수는 별도다.
