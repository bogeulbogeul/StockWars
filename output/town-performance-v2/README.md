## 결과

기존 `StockWars Demo.exe`를 직접 실행하고, 기존 v1 최적화는 켠 채 이번 고정 부품 렌더 묶음만 꺼짐/켜짐으로 비교했다. 입구의 긴 프레임 빈도와 느린 프레임 시간이 감소했다. 평균 FPS 상승을 주된 성과로 판정하지 않는다.

| 구간 | 평균 FPS, v1→v2 | p95 프레임 ms, v1→v2 | p99 프레임 ms, v1→v2 | 50ms 초과 프레임 비율, v1→v2 |
|---|---:|---:|---:|---:|
| 입구 연결로 | 40.6 → 39.2 | 66.7 → 50.0 | 83.5 → 50.1 | 11.18% → 3.64% |
| 광장 남쪽 | 43.6 → 45.3 | 50.1 → 50.0 | 83.3 → 66.7 | 6.83% → 3.75% |
| 북쪽 연결로 | 51.4 → 50.9 | 33.4 → 33.4 | 50.1 → 33.4 | 1.38% → 0.85% |

입구의50ms 초과 비율은 상대적으로 약67% 감소했다. 평균 속도는 약40FPS 수준이며, 이번 표본에서는1.4FPS 낮아졌다. 느린 프레임 완화와 평균 처리량의 수치를 함께 제시한다. 입구 끊김 완전 제거/고정60FPS 또는 모든 장치에서의 개선을 의미하지 않는다.

입구 평균 그리기 호출은 약2,972→1,061회로 줄었다. 실행본의 프레임별 원시 기록은 `walk-results.json`, 조건별 합산은 `summary.json`이다.

## 남아 있던 원인과 최종 구현

실행본에서 항목별로 계측했다. 입구의 가림 판정은 평균 약0.9ms, 좌석은 약0.05ms였고, 긴 지연은 WebGL 렌더 호출에 집중됐다. 상세 표본은 `diagnostic-results.json`이다.

`web/js/components/town3d/TownStaticBatches.js`가 같은 재질·속성 형식·레이어·그리기 우선순위의 작은 불투명 고정 부품을 모은다. 원본 정점·노멀·UV와 변환을 고정 버퍼에 복사하며 폴리곤 단순화나 텍스처 축소는 하지 않는다. 카메라에 가까운 부품부터 인덱스를 정렬해 겹쳐 그리기를 줄인다. 기존 곡률 culling 결과에 따라 보이는 부품의 인덱스만 사용하며, 변하지 않는 정점 버퍼는 매 프레임 갱신하지 않는다. 인덱스 표본 뷰도 재사용한다.

- 512삼각형 이하의 작은 부품만 대상이다. 큰 조형 부품·나무 줄기/수관·투명 재질·스킨/모프·거울 변환·애니메이션 시계 바늘은 원래 경로를 유지한다.
- 추가 버퍼 추산 상한64MiB, 실제 추산 약43.7MiB다. 현재77개 묶음에3,954개 부품이 등록된다. 상한 또는 형식 조건에 맞지 않으면 원본으로 그린다.
- 원본 GLB·텍스처·재질·배치·해상도·안티앨리어싱·지면 곡률·캐릭터·NPC 자세·음악·저장은 변경하지 않았다. 기존 `TownLandscape.js`도 최종적으로 원래 해시와 일치한다.
- 원본 모델은 충돌·좌석·가림·이름 조회의 기준으로 남는다. 렌더 복사본은 레이 질의에 참여하지 않으며 그리기 동안만 원본을 잠시 숨긴 뒤 finally에서 복구한다. 렌더 오류 시 복구도 테스트했다.
- `TownModelScene.js`는 초기 로딩 후 묶음을 만들고, `TownRenderCulling.js`는 기존 화면 밖 제외 이후 렌더 묶음으로 전달한다.

## 실제 실행본 이동 검증

대상: `electron-app/dist/win-unpacked/StockWars Demo.exe`.

Electron28.3.3 / Chromium120.0.6099.291, AMD Radeon(TM) Graphics의 ANGLE Direct3D11, 콘텐츠1264×741, DPR1, 낮 음악 켜짐으로 검증했다. 테스트 프로필을 별도로 사용하고 실제 시작 버튼을 눌러 진입했다. 처음 로딩·음악 준비와 구간 시작의700ms 준비 시간은 제외했다.

기존 실행본의 WASD 처리·충돌·따라가는 카메라·걷기 모션을 사용했다. 대화 대기만 테스트 세션에서 해제하고, 측정 밖에서 구간 시작점으로 배치했다. 측정 중에는 키로 약600게임 단위를 갔다가 돌아왔다. 목표를 넘은 첫 프레임에 키를 놓으므로 한 프레임 이동량 이내 오차가 있다. 이동 도중 좌표를 순간이동시키거나 충돌을 끄지 않았다.

- 입구: `(1960,2290)`→`(1960,1690)`.
- 광장: `(1450,1750)`→`(2050,1750)`.
- 북쪽: `(1300,1160)`→`(1900,1160)`.

꺼짐→켜짐→켜짐→꺼짐 순서로 세 구간을 각각4회 왕복했다. 합계1,955프레임 중1,953프레임에서 walk 상태였고, 불법 충돌 위치·화면 숨김·관찰된 JavaScript 오류는0건이었다. Edge에서 리소스만 연 검증이 아니라 실행본 프로세스에 CDP로 연결한 계측이다. 실행 파일의 경로와 해시는 `executable-hash.json`에 있다.

## 화면·기능 유지 검증

실제 실행본에서 세 구간의 시작·중간·끝9개 지점에 대해 같은 프레임의 새 묶음 꺼짐/켜짐 캔버스를 비교하고 대표 화면과 차이 이미지를 직접 열어 검토했다. 모델 누락이나 실루엣의 눈에 띄는 변화는 확인되지 않았다. 다만 고정 정점 변환의 부동소수점 계산 및 그리기 순서로 **화면 전체의 약0.043~0.079% 픽셀에 미세한 가장자리/AA 차이**가 있어, 픽셀 단위 완전 동일로 기록하지 않는다. 평균 채널 절대차는0~255 중 약0.0036~0.0088이며, 일부 경계 픽셀의 최대 차이는169였다. `pixel-diff.json`·`*-baseline.png`·`*-optimized.png`·8배 강조한 `*-diff.png`를 보존했다.

- 실제 실행본에서 추가13개 좌석의 착석 접촉/주변 교차/유효 출구 검사 통과. 은행 창구 NPC 점유석은 제외됐다.
- 실행본의 마을·안내소·증권사·트레이닝룸에서 실제 E 착석/일어서기, 착석 중 Space 차단, WASD 일어서기 통과. `native-seats.json`과 `native-seat-*.png`를 따른다.
- 웹에서도 기존 `arrivalBench.browser.cjs`의 정류장 충돌 복구·이동·13개 좌석·키보드/버튼·정류장 복귀 검사를 통과했다. `all-seats/web-seats.json`을 따른다.
- 곡률 culling, 숨김 상태 복구, 원본 변환 정점 보존, 카메라 방향별 인덱스 순서, 복사본 레이 제외, 점프/충돌/대화 자세 등 단위 테스트22개 통과.

## 실행본 반영과 정리

`TownModelScene.js`·`TownRenderCulling.js`·`TownStaticBatches.js`를 기존 실행본의 `resources/web/js/components/town3d/`에 동기화했다. 웹/실행본 SHA256 일치를 `deployment-hashes.json`에 기록했다. 수정 전 실행본 파일은 `desktop-backup/`에 보존했다. 설치 프로그램 재빌드는 하지 않았다.

계측을 해제하고 최적화를 켠 상태로 복구한 뒤 테스트 실행본을 정상 종료했다. 실행본 자체 모듈로 좌석을 검사하기 위해 잠시 둔 `__performance_v2_checks/`의 두 검사 파일과 디렉터리는 제거했다. 처음의 외부 소스 경로 검사 실패는 별도 모듈의 입력 등록부가 중복 생성된 검증 구성 문제였고, 실행본 모듈로 다시 검사해 통과했다.

`full-batching-experiment/`·`small-multidraw-experiment/`·`unsorted-merge-experiment/`는 미채택 비교 기록이며 최종 결과와 구분한다. 최종 판정은 최상위 `walk-results.json`·`summary.json`·`native-seats.json`을 따른다.

## 재현 파일

- `setup.cjs`: 실행 중인 테스트 실행본의 시작 화면 조작.
- `walk.cjs`: 세 경로 실제 키 입력 및 새 렌더 묶음 꺼짐/켜짐 왕복 비교.
- `visual-check.cjs`: 실행본의9개 지점 화면 비교 자료 생성.
- `native-seats.cjs`: 실행본 모듈에 상대 연결된 검사 도우미2개를 `resources/web/__performance_v2_checks/`에 잠시 배치한 후 사용한다. 원본 도우미는 `web/tests/AllSeatsCheck.js`·`CollisionAuditScenes.js`다. 완료 후 임시 검사 파일을 제거한다.
