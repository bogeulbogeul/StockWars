# 메신저 2D 디자인 게임 적용 v1

사용자 확정 v1/v2 디자인을 현행 스마트폰 메신저 앱에 연결했다. HTML/CSS/평면 프로필 색상, 아이보리 화면, 큰 이름/채팅 글씨, 상단 ‹ 홈 화면 및 메신저 목록 복귀를 사용한다. 하단 홈·프레임 X는 복원하지 않으며 P 토글/열린 동안 launcher 숨김을 유지한다.

## 실제 기능

- 대화 목록·제목 검색·안 읽은 대화 필터·읽음 위치 저장.
- 친구 검색·요청 보내기·수락 대기·받은 요청 수락/거절·보낸 요청 취소.
- 기존 서버가 정확한 닉네임 검색을 지원하므로 시안의 ID 입력은 닉네임 검색으로 맞췄다.
- 친구1~20명 선택·선택 인원·선택적 방 이름·방 생성·자유 입력 메시지 전송·3초 간격 수신 갱신.
- 기존 stockWarsChat bridge와 서버 API를 그대로 사용하고 경제/저장 스키마/서버 배포를 변경하지 않았다. 메시지는 기존 서버의 500자/속도/100건 정책을 따른다.
- 서버에 연결된 일반 게임에서 친구/채팅을 사용한다. 로컬·전시에서는 해당 안내 및 빈 상태를 표시하고 검색/전송 성공을 꾸미지 않는다. 디자인 예시 친구·NPC 대화·임의 답장을 실제 게임에 심지 않았다. 신규 NPC 메시지 대본/퀘스트는 이번 범위가 아니다.

## 적용·검증

synced-files.txt의7개 웹/기존 실행본 resources/web 파일을 SHA256 일치로 반영했다. 설치 프로그램 재빌드/서버 재배포는 하지 않았다.

node --test Server/presence/friends.test.mjs Server/presence/chat.test.mjs: 로컬 HTTP/임시 파일 권한을 허용한 실행에서10개 통과. 최초 sandbox 실행의 네트워크/rename 권한 오류는 권한 허용 후 해소했다.

scratch/check-phone-messenger.cjs: 실제 게임 안에서 격리 bridge fixture로 로컬 안내·친구 검색/요청/수락·방 생성(실제 숫자 ID)·송신·수신 갱신·문자열 안전 표시·모바일·상단 홈 복귀 확인. 실제 PresenceRegistry를 두 격리 테스트 플레이어와 연결해 UI 요청→상대 수락→방 생성→상대의 송신 메시지 열람→UI 답장 수신까지 확인했다. 실제 계정이나 다른 사람에게 테스트 메시지는 보내지 않았다. web/desktop-checks.json 및 screenshot을 따른다. 스크린샷의 친구/메시지는 검증 데이터이며 게임에 저장하지 않았다. 사용자 최종 온라인 플레이 검수는 별도다.
