## 확인한 결과

오프닝/버스 대사 클릭 → 모아 깨우기 → 안내소 착석·입주 신청·휴대폰 → 집 → 은행 계좌/대출 → 포장 3상자 → 300잎 수령 → 봉투/확인 퀴즈 → 투자 자격시험 3문항 → 트레이닝룸 착석/컴퓨터 → 기업 정보·차트·주문 확인/현물 1주 매수 → 쿠키/지원금/다이어리 → 화분 구매 → 씨앗 4단계 → 일기 쓰기 → 취침 대사/그림책 → 데모 종료/타이틀 복귀를 확인했다.

브라우저 pageerror 0건, HTTP 400 이상 리소스 0건. 최종 현금 6,350잎, 대출 원금 5,000잎, 베리클라우드 1주(850잎), 체력 3칸. 포장 3/3·보수·거래·심기·일기·취침 완료 플래그가 모두 기록됐다.

## 발견하고 수정한 부분

1. **첫 주문 화면에서 매수 버튼이 아래로 밀림** — 전시 거래 안내 문구가 2열 그리드의 첫 셀을 차지해 주문 조건이 오른쪽, 결제 확인이 다음 행으로 밀렸다. StockOrder.js에서 안내 문구를 주문 조건 영역 안으로 옮겼다. 플레이 영상 약 04:00은 수정 전 촬영이다. [수정 후 화면](order-check/web-fixed-order.png)과 실행본 리소스의 같은 검증을 별도로 남겼다.
2. **문 열기 연출을 없앤 뒤 남은 안내** — ‘문을 열고’/‘문 가까이에서 열기’를 문 앞 입장/출입 안내로 정리했다. 촬영에는 수정 전 안내가 포함된다.

두 파일은 웹과 기존 win-unpacked/resources/web에 동일 해시로 반영했다. 웹·실행본 리소스 양쪽에서 첫 매수 안내 순서/사전 거래 차단/매수 완료/모바일 배치를 재검증했고, 1280×800에서 매수 버튼이 하단 대사창 위에 스크롤 없이 표시되는지 확인했다. StockOrder.js·MoaMovementGuideData.js 구문 검사 통과. 설치 프로그램 재빌드는 하지 않았다.

## 남은 판단

가장 큰 문제는 분량이다. 조작 준비 시간을 제외하고 빠르게 대사를 넘긴 편집본도 약 6분이다. 현재의 필수 신청서·3문항 시험·트레이닝룸 왕복·여러 차례 재방문을 모두 유지하면 2분 안팎의 온전한 체험으로 보기 어렵다. 1분 48초 요약본은 홍보/검토용 발췌본이며 이 문제의 해결을 의미하지 않는다. 내용 삭제는 이번 검수에서 임의로 적용하지 않았다.

검수는 이 브라우저의 포장 우선 경로 한 회차다. 주식 우선/모든 선택 분기·설치 EXE 자체의 완주·모든 하드웨어는 이번 촬영의 검증 범위가 아니다. 영상은 1280×800/25fps/H.264이며 게임 60fps 보장의 증거가 아니다. 앞선 구간별 프레임 측정은 ../frame-performance-v1/60fps-README.md를 따른다.
