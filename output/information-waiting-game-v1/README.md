# 안내소 오른쪽 대기 공간 게임 적용

사용자 요청으로 이전 제작본 연초록 2인 소파·원형 목재 테이블·원형 러그·작은 화분을 안내소 오른쪽 앞 공간에 배치했다. `information-coffee-table-v1/build_table.py`의 최종 배치를 그대로 Y-up 게임 좌표로 변환했다. 소파 (320,0,138), 러그 (178,0,138)·1.05배, 테이블 (142,2.7,138), 화분 (142,45.7,138)·.65배다. 테이블 다리는 러그 위, 화분은 상판 위에 접촉한다.

이전 원본 GLB 4개를 web/assets/office/3d/waiting-v1/ 및 기존 실행본 resources/web의 같은 경로에 복사했다. 원본/웹/실행본 바이트 일치는 asset-hashes.json을 따른다. `InformationWaitingCorner.js`에서 런타임에 배치하며 공통 방 초기화의 furnitureReady로 충돌/좌석 생성 전에 로딩을 기다린다. 기존 방 GLB·창문·새싹·지도·가이드북·모아·저장은 변경하지 않았다.

두 좌판을 기존 SeatSurfaces/SeatInteraction에 연결해 E/화면 버튼 착석과 E/이동키 일어서기를 사용한다. 가구는 기존 실내 메시 기반 보행/점프 충돌에 포함하고 얇은 러그는 통행을 막지 않는다. 새 회복 효과는 추가하지 않는다.

`scratch/check-information-waiting.cjs`를 웹과 기존 실행본에 실행했다. 네 모델 로딩·두 좌석·좌석별 착석/일어서기·실제 E키 착석/일어서기·소파/테이블 충돌·러그 위 통행을 확인했다. 입구에서 10단위 격자 탐색으로 1,385개 유효 위치를 확인하고 지도/창구 스툴 접근 및 두 좌석의 유효 출구 접근을 확인했다. 결과는 web-checks.json·desktop-checks.json이다. 테스트의 직접 좌표 설정은 검증 전용이며 게임에 원격 이동을 추가하지 않았다. 실제 전체/착석 렌더를 열어 확인했다. 모든 메시 간 비관통의 수학적 보증과 사용자 최종 시각·플레이 검수는 별도다. 설치 프로그램은 재빌드하지 않았다.
