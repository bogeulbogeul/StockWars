# 건물 출입 캐릭터 불투명 유지 — 2026-10-25

사용자 요청: 건물에 들어갈 때 캐릭터가 투명해지는 현상 방지.

원인은 `doorwayFade`가 출입구 앞에서 소망이/모아의 모든 재질을 복제하고 `transparent=true`, `depthWrite=false`, 거리별 opacity 1→0을 적용하던 처리였다. 이 함수를 제거하고 플레이어 공통 입장·모아 입장·안내소/은행 퇴장 호출을 함께 정리했다. 잡화점/증권사의 문 앞 접근 옵션에서도 `fadeAtDoor`를 제거했다. 이제 출입 중 원래 재질·opacity·transparent·depthWrite를 그대로 유지한다.

기존 걷기 경로·계단 지지 높이·문 개폐·모아 먼저/플레이어 다음 순서·검정 출입구는 유지한다. 모아가 통과를 마친 뒤 외부 모델을 숨기고 실내 모델로 이어지는 기존 처리는 유지한다. 캐릭터를 벽 위에 덧그리는 처리는 추가하지 않으며, 문 뒤로 실제로 들어가면서 가려지는 깊이 판정과 장면 전환은 유지한다. 모델·저장·경제는 바꾸지 않는다.

Node 테스트: `doorwayOpacity`, `doorwayTraversal`, `bankExit`, `informationExit`, `doorwayBlackout` 총 8개 통과. 비동기 걷기의 모든 프레임에서 소망이·모아의 재질 참조/opacity/transparent/depthWrite를 검사한다. 기존 투명화 동작을 요구하던 과거 테스트는 제거했다.

`scratch/check-doorway-opacity.cjs`는 실제 전시 마을을 불러와 소망이의 안내소·집·잡화점·은행·증권사 입장 5건과 모아의 안내소·집·은행 통과 3건을 관찰한다. 매 프레임 원본 재질 참조와 opacity/transparent/depthWrite 변화를 검사하며 문 앞 20~55 거리의 실제 렌더를 저장한다. 결과는 `web-checks.json`/`executable-checks.json`, 렌더는 `web-*.png`/`executable-*.png`다. 원래부터 투명 재질인 부속품은 원본 상태와 비교하며 무조건 불투명 재질로 덮어쓰지 않는다.

변경한 런타임 7개 파일을 웹/기존 실행본 resources/web에 반영하고 SHA256 일치를 확인했다. 설치 프로그램은 재빌드하지 않았다. 자동 검증과 사용자 최종 시각·플레이 검수는 구분한다.

최종 실제 게임 결과: 웹 330프레임·기존 실행본 356프레임, 각각 8개 출입에서 재질/불투명도 변경 0·페이지 오류 0을 확인했다. 문 앞 실제 렌더에서 소망이·모아가 반투명해지지 않음을 확인했다.
