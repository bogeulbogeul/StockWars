# 전 구간 60FPS 목표 모드 — 2026-10-26

사용자 요청으로 마을·모든 공통 실내·버스 카메라에 60FPS 기준 FrameBudget을 적용했다. 게임 좌표/속도/충돌/경제/저장/캐릭터 원본 메시를 변경하지 않는다.

## 구현

- 750ms 단위 실제 프레임 간격을 보고 3D 렌더 해상도를 조절한다. 고해상도 화면의 픽셀 수를 제한하고, 여유가 지속될 때만 천천히 복구한다. UI/대사는 CSS 원래 해상도로 표시한다.
- 새 장면은 GPU 부하를 고려한 보수적인 해상도로 시작한다. 프레임 압력이 지속되면 3D 해상도와 그림자 맵(1024→512)을 낮춘다. 도착 연출의 추정치를 첫 마을 화면에 전달한다.
- 집/안내소/은행/잡화점/증권사/트레이닝룸/모의투자룸은 실내 WebGLRenderer 하나를 공유한다. 같은 캐릭터·텍스처·정점 버퍼를 방문한 방마다 다시 GPU에 올리지 않는다. 활성 실내만 캔버스를 소유해 렌더한다.
- 카메라·캐릭터·가림 물체의 좌표가 같을 때 가림 계산을 최대80ms 재사용한다. 이동/카메라 변화 시 즉시 갱신한다.
- 포장·인벤토리·스마트폰·타이틀 뒤의 3D 렌더를 중단한다. 포장 드래그와 주식 차트 포인터는 화면 프레임당 한 번만 그린다.
- 잡화점의 작은 진열 유리는 굴절용 전체 장면 재렌더 대신 투명 셸을 쓴다. 구매 확대 모델은 원본 재질을 유지한다.
- 버스 연출이 기존 최적화 경로를 우회하던 것을 수정했다. 원경 전용 숲은 나무당26,588→1,052 삼각형으로 경량화했다. 넓은 버스 카메라에서만 기존 외곽 나무의 렌더 지오메트리도 경량본으로 대체하고 렌더 직후 원본을 복원한다. 가까운 마을 나무·충돌 지오메트리는 유지한다.

## 측정과 한계

AMD Radeon(TM) Graphics/D3D11, Edge, 1280×800, DPR1에서 측정. 프레임 표본은 예열 후 약4초씩 기록했다. 59.9FPS는 60Hz 프레임 간격의 실측 반올림값이다. 측정 도중 초기화/셰이더 컴파일·리소스 로딩은 별도이며, 다른 하드웨어/해상도/다른 앱 부하를 포함한 무조건적인60FPS 보장이 아니다. 현재 표본의 간헐적인 느린 프레임도 JSON에 숨기지 않고 기록한다.

- 마을/다섯 실내 정지·이동: desktop-all-segments.json(실행본), all-segments-final.json(중간 웹 표본). 은행/증권사는 더 보수적인 최종 예산으로 재검증한 desktop-final-pressure.json을 우선한다.
- 버스 전경: desktop-arrival-final.json(최종 실행본), arrival-final.json(웹). 처음 약12FPS였던 전용 전경은 경량 숲·원경 나무 대체·차체 정적 묶음 후 최종 실행본 예열 표본59.9FPS, p95 16.8ms, 25ms 초과0프레임. 차체 묶음은 바퀴 등 애니메이션 노드를 제외한다.
- 트레이닝룸/모의투자룸/주식 화면/차트/포장/오프닝: extra-segments-final.json, 약59.9FPS/p95 16.8ms. 이 파일의 초기 버스 표본은 추가 수정 전 결과이므로 버스는 arrival-final.json을 우선한다.

회귀 테스트52개 통과. 기존 실행본 리소스에서 다섯 건물F 입장·퇴장·빠른 전환 통과. 웹·기존 실행본 resources/web에 반영했으며 설치 프로그램 재빌드 및 사용자의 실제 완주 검수는 별도다.

최종 은행/증권사 정지·이동 각4개 표본 모두59.9FPS/p95 16.8ms/25ms초과0프레임. 첫날 밤은 desktop-first-night-final.json에서 동일하게 검증하고 두 대사 클릭 후 종료 복귀를 확인했다. 게임 전체 CSS에서 iframe pointer-events:none이 대사 클릭을 차단하던 기존 문제도 auto로 수정했다.

통합 측정표: results-final.json. 버스 차체 고정 메시 묶음과 바퀴 애니메이션 제외 테스트도 통과했다. 실제 타이틀에서 주식1주 매수/계좌 분리/닫기 복귀 후 오프닝 첫 대사 클릭으로 두 번째 장면 진입을 최종 실행본 리소스에서 확인했다.
