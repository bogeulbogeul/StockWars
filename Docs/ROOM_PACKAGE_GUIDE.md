# 완성형 룸 제작·상호작용·웹 합성 명세

> **개정:** 2026-10-12
> **상태:** 기획 기준 확정 / 구현·기존 데이터 전환 미완료
> **관련 문서:** [아트 가이드](ART_STYLE_GUIDE.md), [월드 시설](MOD_GDD_01_WorldFacilities.md), [룸 상점](MOD_GDD_03_2_JulianFurniture.md), [씬·UI](CORE_GDD_05_ScenesUI.md), [전환 계획](VISUAL_TRANSITION_PLAN.md)

## 1. 목적과 범위

홈 오피스와 일반 건물 내부를 **배치가 완성된 룸 패키지**로 제작한다. 바닥·벽·고정 가구·장식을 묶고 동작·가림·데이터 갱신에 필요한 부분만 분리한다. 모든 가구를 개별 배치용 에셋으로 제작하는 방식을 기본 요구에서 제외한다.

홈 오피스는 완성형 테마 룸을 직접 구매·선택·적용한다. 일반 건물 내부는 시설 운영용 룸이며 플레이어 판매 상품이라는 뜻이 아니다. 여러 구역이 있는 증권사는 구역별 패키지를 둘 수 있다. 별도 미니게임의 전용 화면 전환은 이번 결정에 포함하지 않는다.

마을의 RPG식 탑다운과 실내의 아이소메트릭을 유지한다. 픽셀아트는 필수가 아니며 최종 화풍과 캐릭터 외형은 후속 결정이다. 임시 룸으로 실내외 왕복과 상호작용부터 검증한다.

## 2. 확정 범위

- 가구의 위치·방향과 벽·바닥 구성은 제작자가 룸 단위로 정한다. 유저의 가구 자유 이동·회전, 벽지/바닥 단품 조합을 기본 기능에서 대체한다.
- 고정 가구라도 앉기·눕기·거래·옷장 열기·시설 이용 등 상호작용은 유지한다.
- 룸은 한 장의 평면 그림만을 의미하지 않는다. 배경, 필요한 분리 레이어, 좌표와 상호작용 데이터를 묶은 단위다.
- 문·책상·좌석 등 핵심 기능의 위치는 홈 테마 간 가능한 범위에서 공유한다. 다른 위치를 쓰는 룸은 자체 접근·복귀 지점을 검증한다.
- 정해진 소품 자리 교체는 향후 확장 후보이며 이번 범위에서 구현·판매를 확정하지 않는다.
- 룸 그림만으로 수수료·회복·시설 권한 등 게임 효과가 달라지지 않는다. 효과는 기존 게임 로직을 호출하며 구 가구 버프의 이관은 별도 결정한다.

## 3. 룸 패키지 구성

| 요소 | 포함 내용 | 제작 기준 |
| :--- | :--- | :--- |
| 기본 배경 | 바닥·벽·고정 장식·가림이 필요 없는 가구 | 가능한 범위에서 통합 이미지 |
| 가림 요소 | 책상 앞면·카운터·의자 앞부분·이불 등 | 투명 레이어와 표시 조건·깊이 정보 |
| 동적 표시 | 모니터·전광판 내용·시계·조명 등 | HTML/CSS 요소 또는 별도 그림, 배치 좌표·표면 변환 |
| 상호작용 | 문·좌석·침대·옷장·접수대 등 | 클릭 영역·접근 위치·정렬 위치·방향·행동 |
| 이동 정보 | 이동 가능 영역·장애물·입구·복귀 위치 | 논리 좌표 데이터 |
| 캐릭터·NPC | 플레이어·직원·안나 등 | 배경에 굽지 않는 독립 표시와 상태 |
| 메타데이터 | ID·버전·시점·크기·참조 파일·검수 상태 | 패키지 전체를 같은 버전으로 관리 |

상호작용 가구 전체를 반드시 분리할 필요는 없다. 캐릭터가 가구를 사용하거나 앞뒤로 지나갈 때 필요한 부분만 분리한다. 분리된 앞면을 원본 배경에 중복으로 남겨 두어 캐릭터가 두 겹에 가려지지 않도록 납품한다.

## 4. HTML/CSS와 JavaScript 역할

| 예시 | CSS/HTML 표현 | JavaScript 및 게임 로직 |
| :--- | :--- | :--- |
| 증권사 전광판 | 글자·색·스크롤·화면 테두리 안쪽 표시 | 실제 시세 연결·갱신·구독 해제 |
| 컴퓨터 | 화면 내용·상태 강조 | 접근 후 거래 UI 열기 |
| 조명 | 밝기·색·점등 효과 | 상황에 맞는 효과 활성화 |
| 벽시계 | 바늘·숫자 표시 | 게임 시간 연동 |
| 문·시설 | 선택 강조·행동 안내 | 이동·이용 가능 여부·씬 전환 |

CSS는 표현을 담당하며 거래 판정·충돌·보상·저장·시설 접근 권한을 대체하지 않는다. 화면 안의 숫자와 글자를 배경에 구워 넣지 않는다. 데이터가 없거나 갱신이 끊기면 임의의 실시간 값 대신 로딩/미연결 상태를 표시한다.

장식용 요소는 입력을 통과시키고 클릭 가능한 요소만 입력을 받는다. 캐릭터 이동과 버튼 클릭이 동시에 실행되지 않도록 입력 우선순위를 정한다. 클릭 영역에는 이름과 키보드 접근 또는 동일 기능의 접근 가능한 버튼을 제공한다. 지속 점멸·자동 움직임은 효과 감소 설정을 고려하고, 씬을 떠날 때 타이머·구독을 정리한다.

HTML/CSS는 웹 구현 방식이다. 다른 클라이언트에서는 같은 룸 데이터와 기능을 대응하는 렌더러로 구현할 수 있다. 이 문서가 현재 엔진 교체를 요구하지는 않는다.

## 5. 공통 좌표와 화면 크기 대응

룸 패키지에 기준 캔버스 크기, 원점, 그리드 투영, 기준 배율을 기록한다. 기존 [아트 가이드](ART_STYLE_GUIDE.md)의 공통 셀 규격과 캐릭터 H=90 기준을 이어받으며, 제안 수치와 룸별 현재 적용값을 구분한다. 8×8은 기존 홈의 논리 공간이며 모든 건물·테마의 필수 크기가 아니다.

- 논리 바닥 좌표는 이동·충돌·접근·접지 기준으로 사용한다.
- 룸 로컬 화면 좌표는 배경 레이어와 벽면 전광판 등 표면 요소 배치에 사용한다. 두 좌표를 명시적으로 구분한다.
- 배경·캐릭터·상호작용 영역·동적 요소·가림 레이어에 동일한 룸 변환(이동/카메라/균일 확대)을 적용한다.
- 화면 입력은 공통 변환의 역변환으로 룸 좌표에 매핑한 뒤 판정한다. 브라우저 창 기준의 독립 고정 픽셀 배치는 사용하지 않는다.
- 아이소메트릭 벽의 전광판 내용은 해당 표면의 모서리·축에 맞춰 CSS 변환과 잘라내기를 적용한다. 룸이나 가구 원본 전체를 비균일 변형해 투영 오류를 숨기지 않는다.
- 화면 크기에 따라 룸을 균일하게 맞추거나 카메라로 보여준다. 레터박스·스크롤·배율 변경 시 입력 위치도 검증한다.
- 거래 창·메뉴 같은 화면 UI는 룸 변환 밖에서 읽기 쉬운 크기로 표시한다.

자유 배치를 없애도 논리 그리드는 이동·충돌·제작 정렬에 계속 사용할 수 있다. 유저용 배치 편집기와 개발용 디버그 그리드를 구분한다.

## 6. 가림과 캐릭터 합성

### 캔버스 표시 해상도 (2026-10-16)

룸 논리 좌표·캐릭터 비율, 화면 CSS 크기, 캔버스 내부 픽셀 수를 구분한다. Canvas 기반 룸은 실제 화면에 들어가는 룸의 크기와 `devicePixelRatio`를 기준으로 내부 해상도를 정한다. 낮은 고정 해상도로 방 전체를 축소 렌더한 뒤 CSS로 확대하지 않는다. UI 확대가 반영된 `getBoundingClientRect()`를 측정한 경우 게임 UI 배율을 다시 곱하지 않는다.

증권사는 논리 좌표1760×894와 캐릭터 비율용 `CIPHER_ROOM_SCALE=0.6`을 유지한다. 이0.6은 내부 해상도 축소에 사용하지 않는다. 룸의 화면 맞춤 배율은 `min(표시 폭/1760, 표시 높이/894)`이며 내부 폭·높이는 맞춤 크기에 DPR을 곱해 반올림한다. 내부 픽셀 기준 균일 변환과 가운데 정렬로 그리며, 클릭 좌표·HTML 전광판은 기존 CSS 화면 크기와 레터박스를 기준으로 변환한다.

예를 들어1920×1080의 표시 영역은 DPR1에서1920×975, DPR2에서3840×1951의 내부 캔버스를 사용한다. 창 크기 변경과 모니터/DPR 변경에 대응하고, 화면이 닫혀 크기가0인 동안에는 캔버스를0으로 초기화하지 않는다. 원본 이미지에 없는 세부를 복원하는 기능은 아니며, 확대 시 남는 원본 해상도 한계와 구분한다. 현재 적용 범위는 증권사 통합 룸이다.

배경 위에 모든 가림 이미지를 무조건 올리는 방식은 사용하지 않는다. 캐릭터가 가구 앞에 있을 때는 캐릭터가, 뒤에 있을 때는 가구가 앞에 보여야 한다. 바닥 접지 기준과 가림 영역을 이용한 깊이 정렬 또는 상태별 표시 규칙을 룸마다 검증한다.

의자 등받이·캐릭터·책상 앞면은 상황에 맞는 순서로 합성한다. 침대는 누운 캐릭터 위에 이불 레이어를 올릴 수 있다. 긴 카운터나 교차하는 물체는 하나의 깊이 값으로 해결되지 않으면 필요한 구간만 나눈다. 벽·높은 가구가 플레이어를 숨기는 경우의 숨김/투명화 범위는 검증 후 정한다.

DOM/CSS 변환의 stacking context와 캐릭터 렌더러의 깊이 정렬이 서로 어긋나지 않도록 한다. 캐릭터를 하나의 캔버스에 그리는 경우에도 가림 레이어를 함께 그리거나 렌더 패스를 나누는 등 같은 순서를 구현해야 한다. 구체적 렌더 방식은 후속 구현 선택이다.

## 7. 상호작용 계약

각 지점은 다음을 가진다. 실제 스키마 이름은 구현 시 정하며 아래는 필요한 의미의 목록이다.

| 항목 | 의미 |
| :--- | :--- |
| ID·행동 종류 | 거래, 의자 앉기, 벤치 휴식, 눕기, 옷장, 문, 시설 이용 |
| 입력 영역 | 클릭/터치 가능한 영역, 표시 이름 |
| 접근 위치 | 걸어서 도착할 바닥 좌표·필요 거리 |
| 정렬 기준 | 좌석/침대/손 등의 룸 로컬 기준점과 캐릭터 방향 |
| 모션·가림 | 진입·유지·이탈 모션과 레이어 조건 |
| 이탈 위치 | 중단·완료 후 돌아갈 안전한 바닥 좌표 |
| 이용 조건 | 시설 영업·권한·현재 상태·점유 여부 등 기존 판정 |
| 대체 처리 | 접근 불가, 자리 점유, 모션 미준비 시 안내 또는 검증용 동작 |

흐름은 **선택 → 이용 조건 확인 → 접근 이동 → 도착 및 조건 재확인 → 정렬·모션/기능 실행 → 이탈·복귀**다. 이동 불가 지점으로 순간이동해 기능을 실행하지 않는다. 문은 도착 후 목적 씬·스폰 위치로 이동한다.

연속 클릭·이동 취소·모달 닫기·씬 이탈·룸 변경 중 중복 실행과 좌석 점유 누락을 막는다. 다중 사용자가 있는 시설에서는 공유 좌석·시설의 점유 소유권을 권위 있는 게임 상태로 관리한다. 완성 모션이 없을 때도 임시 캐릭터로 접근·정렬을 검증하되 제작 완료로 표시하지 않는다.

## 8. 홈 테마 판매와 적용

홈 테마는 벽·바닥·고정 배치·효과·상호작용 데이터를 포함한 완성형 상품이다. 상품 카드에 전체 미리보기, 고정 배치임을 알리는 설명, 포함 기능, 가격과 보유 여부를 표시한다. 일반 시설 룸은 판매 목록에서 구분한다. [룸 상점](MOD_GDD_03_2_JulianFurniture.md)이 판매 명세다.

적용 시 새 패키지 로드·필수 지점·안전 스폰 유효성을 확인하고 현재 상호작용을 정상 종료한 뒤 룸을 교체한다. 성공 후 착용 룸 ID를 저장한다. 실패하면 기존 룸과 상태를 유지한다. 룸 변경으로 캐릭터·NPC가 가구 속에 남지 않도록 한다. 재접속 시 동일 룸을 복원하며 참조가 깨지면 검증된 기본 룸으로 복구하고 보유 권리는 보존한다.

## 9. 제작·전환 순서

1. 홈 오피스 1종과 대표 시설 내부 1종의 고정 배치를 정한다.
2. 필요한 기능과 이동 동선을 먼저 정하고 배경에 포함할 부분·가림·동적 표시 부분을 나눈다.
3. 임시 에셋과 좌표 데이터로 문·책상·좌석·침대·시설 기능을 검증한다.
4. 동일 기준으로 최종 이미지를 제작하고 실제 배율에서 정렬·가림·CSS 표면을 확인한다.
5. 다른 테마/시설로 확장한다. 최종 화풍·캐릭터 착수는 기존 전환 우선순위를 따른다.

기존 가구 에셋·배치 저장·보유 아이템은 즉시 삭제하거나 룸으로 자동 환산하지 않는다. 가격·가구 버프·은행 테마 개수 조건·전당포 매각·압류·수집 보상은 룸 단위로 전환할 정책을 별도 검토한다. 해당 정책과 마이그레이션이 정해지기 전 기존 데이터 파괴 또는 밸런스의 자동 승계를 금지한다.

- [ ] 전체 그림이 깔끔하고 이동 통로·문·기능 가구가 구분된다.
- [ ] 배경과 분리 레이어에 중복 그림·빈 구멍이 없다.
- [ ] 창 크기·카메라·배율 변경 후 그림·캐릭터·입력 영역이 정렬된다.
- [ ] 가구 앞뒤 이동, 의자 앉기·침대 눕기의 가림이 맞는다.
- [ ] 장식 효과가 이동·버튼 입력을 가로채지 않고 실제 데이터와 표시가 일치한다.
- [ ] 접근 불가·반복 클릭·점유·취소·씬 이탈 처리가 안전하다.
- [ ] 홈 룸 교체·실패·재접속과 마을 왕복 위치가 검증된다.
- [ ] 기존 보유/배치/효과/경제 규칙 이관 여부를 기록한다.

이 문서는 기획·제작 계약이다. HTML/CSS 합성, 룸 구매와 기존 저장 데이터 이관이 구현 완료되었다는 뜻이 아니다.
