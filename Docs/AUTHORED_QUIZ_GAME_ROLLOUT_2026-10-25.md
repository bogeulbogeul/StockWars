## 출제와 보상

[회사별 원고](RumorQuizzes/README.md)의 전 8개 업종·72개 회사·288개 사건·864문항을 게임에 연결했다. 현재 표시된 해석 단계가 1~3이면 첫 문항, 4~6이면 두 번째 문항, 7~10이면 세 번째 문항을 하나만 표시한다. 같은 구간에서는 같은 질문·보기·정답·해설을 쓰며, 출제 당시의 실제 단계 본문을 함께 보관한다. 가루·임시 분석력 효과를 포함해 기존 본문 해석 단계 계산을 그대로 따른다.

자동 문장 추출형 문항을 회사별 집필 문항으로 교체했다. 선택지·정답 위치·해설은 원고 그대로이며 숨은 진위·향후 주가 정보를 정답 판정에 사용하지 않는다. 낮은 단계의 비유 본문은 다음 단계에서 다른 표현으로 바뀔 수 있어, 인용문을 억지로 이어 붙이지 않고 현재 공개된 정식 단계 본문으로 출제한다. 원고의 최소 근거 단계도 정식 본문과 대조한다. 없는 사건·잘못된 단계·정식 본문과 다른 텍스트는 출제하지 않는다. 정답·해설·근거는 문제 시작 응답에서 제외하고 제출 후 기존 UI로 해설한다.

정답 숙련도 +1·오답 후 재도전 동일 보상·플레이어별 사건당 한 번 지급을 유지한다. 같은 사건의 단계 구간이 바뀌어도 별도 보상을 만들지 않는다. 사본·선물·재구매·재열람·재접속 역시 기존 `analysisGrowth.awarded[rumorId]`를 공유한다. 분석력 요구량 6·10·16·20, Lv.1→10 정답 110개와 최대 단계 무보상 복습도 유지한다.

## 저장 호환과 구성

기존 분석력 단계·숙련도·지급 이력·보유 기록은 초기화하거나 환산하지 않는다. 업데이트 전 자동 문항의 세션 키는 새 문항과 다르므로 오래된 화면의 제출을 거절하고 재열람을 안내한다. 다시 문제를 열면 문항 세션만 교체하며 지급 이력은 보존한다. 미보상 사건은 새 문항 정답에 +1, 이미 보상받은 사건은 새 문항 정답에도 +0이다. 새 문항의 오답 기록은 재접속 후 같은 단계에서 복원된다.

`scratch/build-authored-quiz-runtime.py`가 72개 회사 Markdown을 읽어 `web/js/data/rumorQuizzes/`의 회사별 모듈과 `authoredRumorQuizzes.js`를 만든다. 런타임 데이터는 72개 파일로 분리했고 회사별 파일은 15줄, 집계 모듈은 147줄이다. 문항 선택과 검증은 `RumorQuizQuestions.js`, 보상·저장은 기존 `AnalysisGrowth.js`, 표시는 기존 `RumorQuizCard.js`가 맡는다. 문항을 수정하면 회사별 원고를 먼저 수정하고 컴파일·검증·실행본 동기화를 다시 한다. 과거 원고 작성용 스크립트를 재실행해 최신 적용 상태를 덮어쓰지 않는다.

## 검증과 실행본 범위

- 핵심 테스트 17개 통과: 864문항의 질문·보기·정답·해설·근거가 원고와 일치하며, 2,880개 표시 단계 모두 올바른 구간의 문항을 선택한다. 전체 승급·시작 단계·오답 재도전·사본·재접속·단계 변경의 중복 보상 방지, 구형 세션 교체와 지급 이력 보존을 확인했다.
- 전체 테스트 337개 중 334개 통과. 실패 3개는 `removedCharacterAssets.test.mjs`의 토리·봉봉 삭제 기대와 현행 재도입 상태 충돌, Node의 로컬 GLB fetch 제한이다. 이번 퀴즈 테스트는 모두 통과했다.
- 웹·기존 실행본 리소스 각각 실제 앱 초기화 후 게임 컴포넌트·CSS에서 1·3·4·6·7·10단계 문항·보기 일치와 한 문항 표시를 확인했다. 오답→재접속→정답 +1, 사본·재접속·단계 상승 후 +0, 6개 사건 승급·본문 갱신, 모바일 스크롤·겹침 방지도 통과했다. 두 환경 모두 JavaScript 예외·JS/CSS 요청 실패 0건이다.
- 기존 실행본 `electron-app/dist/win-unpacked/resources/web/`에 데이터 73개·엔진 2개, 총 75개 파일을 복사하고 SHA-256 일치를 확인했다. 설치 프로그램은 재빌드하지 않았다. 실행 중인 게임은 재실행해야 새 모듈을 읽는다. 브라우저 기반 리소스 검증과 Electron 직접 실행·사용자의 최종 플레이 검수는 구분한다.
