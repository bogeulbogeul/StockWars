# StockWars 픽셀 캐릭터 파츠 분리 및 커스터마이징 가이드

> **개정:** v3.0 / 2026-09-28
> **상태:** 제작 구조 정의 / 수치 규격은 프로토타입 검증 예정
> **연관 문서:** [아트 가이드](ART_STYLE_GUIDE.md), [캐릭터 생성](CORE_GDD_08_CharacterCreation.md), [그래픽 전환 계획](VISUAL_TRANSITION_PLAN.md)

기존 문서의 링크를 유지하기 위해 파일명 `part_separation_guide_512.md`는 유지한다. 파일명의 512는 이전 규격의 흔적이며 새 캐릭터 해상도를 뜻하지 않는다. 본문은 기존 512×512 스켈레탈 관절 절단·Spine·안티에일리어싱 기준을 대체한다. 이번 개정은 에셋이나 런타임 구현 완료를 의미하지 않는다.

## 1. 목표와 제작 방식

아트 가이드에 보관한 [사용자 제공 캐릭터 디자인 샘플](References/player-character-style-reference.png)처럼 **큰 머리, 작은 몸, 또렷한 눈과 헤어 실루엣**을 가진 픽셀 캐릭터를 지향한다. 첨부 이미지는 비율과 분위기 참고이며 원본 픽셀 해상도나 파츠 구조를 확정하는 자료는 아니다.

공통 몸체 위에 얼굴·헤어·의상·장식을 겹쳐 조합한다. 기본 애니메이션은 **프레임별 픽셀 스프라이트**로 제작하고 모든 파츠가 같은 방향·동작·프레임을 공유한다. 팔꿈치·무릎마다 관절 조각을 만드는 이전 방식은 기본 규격으로 사용하지 않는다. 앞뒤 가림에 필요한 부분만 분리한다.

월드와 동일한 비스듬한 탑다운 시점으로 앞·뒤·좌·우를 제작한다. 의상 조합의 다양성을 목표로 하며 특정 게임의 내부 구현을 재현하는 명세는 아니다.

## 2. 공통 몸체와 캔버스

| 항목 | 제작 원칙 | 확정 상태 |
| :--- | :--- | :--- |
| 기본 체형 | 프로토타입은 공통 몸체 1종으로 의상 호환성을 확인 | 검증용 범위 |
| 캔버스 | 64×64를 첫 후보로 비교. 큰 헤어·모자·꼬리 여백까지 확인 | 권장 시작안, 미확정 |
| 등신과 몸체 크기 | 약 2등신 SD를 기준으로 큰 머리·작은 몸을 표현. 모자·귀·꼬리는 등신 계산에서 제외 | 디자인 목표 확정, 정확한 픽셀 수는 검증 |
| 포맷 | 게임용 PNG RGBA, 투명 배경, 원본 픽셀 크기 유지 | 제작 기준 |
| 경계 | 기본 몸체·의상은 선명한 픽셀 경계. 부드러운 안티에일리어싱 및 반투명 테두리 배제 | 제작 기준 |
| 좌표 | 좌상단 원점, 오른쪽 +X, 아래쪽 +Y. 발바닥 접지점을 공통 기준으로 사용 | 제작 기준, 좌표 수치 미정 |
| 표시 | 정수 배율과 최근접 샘플링을 기본으로 검증 | 화면별 배율 미정 |

모든 파츠의 프레임 캔버스 크기와 접지점은 동일해야 한다. 머리·눈·어깨의 위치는 방향별 몸체 템플릿으로 고정한다. 걷는 동안 머리가 움직이면 얼굴과 헤어도 같은 프레임의 위치에 맞춰 그린다. 기본 몸체가 확정되기 전에 의상을 대량 제작하지 않는다.

초기 내보내기는 투명 여백을 잘라내지 않는 동일 크기 셀을 사용한다. 추후 아틀라스에서 여백을 제거한다면 원래 셀 크기와 오프셋을 함께 보존해야 한다.

## 3. 커스텀 슬롯과 실제 그림 레이어

유저가 선택하는 **장착 슬롯**과 그림의 **렌더링 레이어**는 다르다. 헤어 하나를 선택해도 앞머리·뒷머리 여러 레이어가 함께 바뀐다.

| 장착 슬롯 | 그림 구성 | 주의점 |
| :--- | :--- | :--- |
| 몸체·피부 | 기본 몸체, 필요 시 앞쪽 손/팔 | 몸체별 의상 호환 규격을 식별한다. 피부색 변경은 얼굴·손·다리에 함께 적용한다. |
| 얼굴 | 눈·입·표정 | 뒤 방향에서는 숨김. 측면용 얼굴을 따로 제작한다. |
| 헤어 | 몸 뒤 머리, 얼굴 앞 머리, 필요 시 정수리 영역 | 앞뒤 방향에 따라 그리는 순서가 달라진다. |
| 상의 | 몸통, 필요 시 뒤쪽/앞쪽 소매 | 손과 소매를 함께 검토한다. |
| 하의 | 바지·치마 | 걸음 프레임과 다리 가림을 맞춘다. |
| 신발 | 발에 맞춘 좌우 신발 | 몸체의 발이 밖으로 새어 나오지 않도록 확인한다. |
| 한벌옷 | 상·하체를 덮는 의상과 필요한 소매 | 장착 중 상의·하의 렌더링을 숨긴다. |
| 모자 | 모자 본체, 필요 시 앞쪽 챙 | 헤어 숨김/대체 규칙을 가진다. |
| 머리·얼굴 장식 | 귀, 리본, 안경 등 | 장식 귀와 몸체 귀를 구분하고 슬롯 충돌을 명시한다. |
| 등 장식 | 가방·망토 | 앞을 볼 때 몸 뒤, 뒤를 볼 때 몸 위에 표시한다. |
| 꼬리 | 뒤쪽 또는 측면 돌출 부분 | 방향별 위치와 가림 순서를 확인한다. |

한 아이템에 필요 없는 레이어는 만들지 않아도 된다. 숨김용 마스크와 추가 레이어는 실제 겹침 문제가 있는 경우에만 추가한다.

## 4. 방향·동작·프레임 계약

방향 이름은 `down`(앞), `up`(뒤), `left`, `right`로 통일한다. 이는 화면 이동 방향이며, 캐릭터의 해부학적 좌우와 혼용하지 않는다.

| 동작 | 초기 제안 | 비고 |
| :--- | :--- | :--- |
| `idle` | 방향당 1프레임 | 정지 상태 호환성부터 확인 |
| `walk` | 방향당 4프레임 | 보행과 옷 흔들림을 검증한 뒤 수 조정 가능 |
| 앉기·운반·작업 | 초기 검증 이후 별도 정의 | 지원 여부와 의상 대응 비용을 확인한 뒤 추가 |

위 제안이면 각 파츠에 **4방향 × (정지 1 + 걷기 4) = 20개 프레임 위치**가 필요하다. 이는 20장을 모두 새로 그려야 한다는 뜻은 아니다. 변하지 않는 그림은 명시적으로 재사용할 수 있다. 긴 머리나 치마처럼 변형되는 파츠는 프레임별 보정이 필요하다.

- 몸체·옷·헤어는 하나의 애니메이션 시계와 동일한 프레임 번호를 사용한다.
- 각 프레임 지속 시간도 몸체 템플릿과 공유한다. 구체적인 재생 속도는 걷기 테스트 후 확정한다.
- 좌우 반전 재사용은 대칭 디자인에만 허용한다. 비대칭 앞머리·문양·장식은 별도 방향을 제작한다.
- 누락 프레임은 검수에서 오류로 취급한다. 재사용할 경우 대응 프레임을 명시한다.
- 캐릭터 전체를 늘이거나 임의 각도로 회전하여 동작을 대신하지 않는다.

## 5. 겹침 순서와 숨김 규칙

단일 고정 레이어 순서를 모든 방향에 적용하지 않는다. **몸체 내부의 앞뒤 순서**와 **월드에서 캐릭터가 가구 앞뒤에 서는 순서**도 별도로 처리한다.

아래는 방향별 합성 시작안이다. 왼쪽부터 뒤에서 앞으로 그린다. 아이템 형태에 따른 예외는 데이터로 명시한다.

| 방향 | 기본 합성 예 |
| :--- | :--- |
| 앞 (`down`) | 등 장식·뒤쪽 머리 → 몸체 → 하의·신발·상의 → 앞쪽 손/소매 → 얼굴 → 앞머리 → 모자·앞쪽 장식 |
| 뒤 (`up`) | 몸체 → 하의·신발·상의 → 등 장식 → 뒤에서 보이는 긴 머리 → 모자·뒤쪽 장식. 얼굴과 정면 앞머리는 숨김 |
| 좌/우 | 먼 쪽 장식·팔/소매 → 몸체와 의상 → 가까운 쪽 팔/소매 → 측면 얼굴·헤어 → 모자·장식 |

몸체와 의상은 같은 실루엣을 기준으로 한다. 옷 아래 몸체가 튀어나오는 경우에는 해당 프레임의 피부 영역을 마스크로 숨긴다. 피부와 옷을 한 장으로 합쳐 저장하지 않아야 피부색 교체가 유지된다.

### 아이템 호환 규칙

- **모자:** `full`(기본 헤어), `hat_fit`(모자 대응 헤어), `hidden`(헤어 전체 숨김) 같은 표시 모드를 정의한다. `hat_fit`은 모드 이름만 지정하는 것으로 끝나지 않으며 실제 대응 그림이나 검증된 마스크가 필요하다.
- **한벌옷:** 상의·하의의 선택 값은 보존하고 렌더링만 숨긴다. 벗으면 기존 선택을 복구한다.
- **귀 장식:** 모자와 동시 착용 가능 여부, 헤어 뒤/앞 표시 여부를 아이템에 기록한다.
- **긴 머리와 가방:** 방향별 우선순위를 정한다. 호환이 어려운 조합은 대체 그림이나 장착 제한을 명시한다.
- **미지원 조합:** 조용히 깨진 그림을 표시하지 않는다. 검증된 기본 대체 외형 또는 명시적인 선택 제한을 사용한다.

## 6. 색상 커스터마이징

피부는 기존 5종 선택지를 유지하되, 픽셀아트용 밝은색·기본색·그림자색을 실제 화면에서 다시 검증한다. 이전 문서의 HEX 값은 자동 승계하지 않는다.

피부·헤어·의상별로 색상 영역을 구분한다. 동일한 RGB가 사용되었다는 이유로 모든 파츠를 함께 바꾸지 않는다. 팔레트 인덱스 또는 영역 마스크를 이용한 교체를 권장하며 눈 흰자·윤곽선·장식 색상은 보호한다. 모든 색상 조합을 별도 PNG로 복제할 필요는 없다.

## 7. 원본·내보내기·데이터 구조

아래 경로와 데이터 이름은 신규 제작을 위한 제안이며 현재 로더에 구현되었다는 뜻은 아니다.

```text
characters/player/
  source/
    body_base_v1.aseprite
    hair_bob_01.aseprite
    top_shirt_01.aseprite
  exported/
    body_base_v1/base_walk_down.png
    hair_bob_01/hair_back_walk_down.png
    hair_bob_01/hair_front_walk_down.png
    top_shirt_01/torso_walk_down.png
  metadata/
    body_base_v1.json
    hair_bob_01.json
    top_shirt_01.json
```

- 편집 원본은 레이어와 프레임을 보존하는 형식으로 관리한다. Aseprite 사용 시 동작·방향별 태그를 사용한다.
- 파일명은 `{renderLayer}_{action}_{direction}.png`를 기본으로 하고, 아이템 ID별 디렉터리로 구분한다.
- 각 PNG는 해당 동작의 프레임을 왼쪽부터 나열한 동일 크기 셀의 시트다. 처음에는 자동 트리밍·패킹을 사용하지 않는다.
- 메타데이터에는 `itemId`, `slot`, `bodyTemplateVersion`, `cellSize`, `anchor`, 방향·동작별 시트와 프레임 수·지속 시간, 색상 영역, 표시 순서, 숨김 규칙, 지원 조합을 기록한다.
- 몸체 규격이 바뀌면 템플릿 버전을 올리고 의상 호환성을 다시 검수한다.

## 8. 제작 순서

1. 공통 몸체 후보의 정면을 실제 게임 표시 크기로 비교하고 캔버스·머리 비율을 정한다.
2. 같은 몸체의 뒤·좌·우를 만들고 방향별 눈·머리·어깨·접지점 템플릿을 고정한다.
3. 4방향 걷기를 만든 뒤 각 프레임 위에 옷을 그릴 수 있는 공통 원본을 배포한다.
4. 기본 의상 한 세트로 소매·손·다리 겹침을 검증한다.
5. 헤어·얼굴·의상을 교체하고 모자를 씌워 숨김 규칙을 검증한다.
6. 홈 오피스와 마을에서 이동시키며 월드 대비 크기와 가림을 확인한다.
7. 검증 결과를 아트 가이드와 이 문서에 반영한 뒤 아이템 종류를 늘린다.

AI 생성 이미지는 디자인 탐색과 기준 이미지에 활용한다. 생성된 방향별 그림의 비율·좌표·픽셀 밀도가 자동으로 일치한다고 가정하지 않는다. 게임용 파츠는 공통 몸체 템플릿에서 직접 정렬·수정하고 분리한다.

## 9. 최소 검증 세트와 완료 조건

**권장 시작 구성:** 몸체 1종, 헤어 2종(짧은 머리·긴 머리), 얼굴 2종, 상의 2종, 하의 2종, 신발 1종, 모자 1종. 기존 초기 헤어 4종과 피부색 5종 기획을 축소하는 결정이 아니라 제작 방식 확인용 샘플이다.

- [ ] 캔버스·접지점·몸체 비율과 버전이 기록되어 있다.
- [ ] 모든 파츠가 4방향 정지·걷기에서 같은 프레임과 시간을 사용한다.
- [ ] 샘플 조합 전체에서 목·손목·허리·발목이 어긋나거나 빈틈이 생기지 않는다.
- [ ] 짧은 머리·긴 머리 모두 모자와 함께 정상 표시된다.
- [ ] 피부색을 바꾸어도 옷·눈·윤곽선 색이 바뀌지 않는다.
- [ ] 뒤 방향에서 얼굴이 보이지 않고 헤어·등 장식 순서가 자연스럽다.
- [ ] 큰 장식과 걷는 손발이 캔버스 밖으로 잘리지 않는다.
- [ ] 실제 화면 크기에서 얼굴·옷이 읽히며 정지·이동 중 픽셀 경계가 선명하다.
- [ ] 홈 오피스와 마을에서 캐릭터 크기·접지·가구 가림이 일관된다.
- [ ] 추가되는 한벌옷·가방·귀 장식은 각 슬롯의 숨김·충돌 규칙까지 검증한다.
