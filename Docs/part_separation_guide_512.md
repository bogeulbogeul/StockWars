# StockWars 완성형 캐릭터 스타일 제작 가이드

> **개정:** v4.0 / 2026-09-28
> **상태:** 완성형 외형 방식 확정 / 에셋 제작·런타임 전환 예정
> **관련 문서:** [아트 가이드](ART_STYLE_GUIDE.md), [캐릭터 생성](CORE_GDD_08_CharacterCreation.md), [스타일 상점](MOD_GDD_03_3_ClaireApparel.md)

기존 링크를 유지하기 위해 `part_separation_guide_512.md` 파일명은 유지한다. 이전 파츠 조립, 피부 팔레트 5종 × 헤어 4종, 파츠 PNG 목록은 본 개정으로 대체하며 신규 제작 요구사항으로 사용하지 않는다. 파일명의 512는 현행 제작 해상도가 아니다.

## 1. 확정된 제작 단위

**몸체·얼굴·피부색·헤어·상의·하의·신발·포함 장식을 합친 완성형 캐릭터 외형**을 하나의 `styleId`로 제작한다. 유저는 외형을 통째로 선택·구매·착용한다. 독립 얼굴·피부색·헤어·의상·신발 선택 및 혼합 착용은 제공하지 않는다.

스타일은 같은 플레이어의 외형이다. 교체해도 닉네임, 투자 성향, 레벨, 자산, 인벤토리, 안나와의 관계가 다른 인물의 데이터로 바뀌지 않는다. 캐릭터마다 별도 직업·고유 스킬을 추가하는 결정이 아니다.

## 2. 화풍과 참고 자료

![완성형 스타일 참고](References/player-compact-pixel-style-reference.png)

작은 얼굴, 간결한 눈·입, 헤어와 옷의 덩어리, 전체 실루엣으로 스타일을 구분한다. 참고 이미지의 대각선 자세나 판타지 의상은 필수 규칙이 아니다. StockWars의 현대 생활·투자 배경과 비스듬한 탑다운 시점을 유지한다.

이전 큰 눈 기본형과 파츠별 프리뷰는 이력 참고 자료이며 최신 제작 표준이 아니다. 정확한 등신·픽셀 해상도는 실제 화면 검증 후 정한다.

## 3. 제작 원칙

- 여러 스타일은 공통 몸체 비율·접지점·방향별 동작 틀을 공유한다. 편집 원본에서 몸체·헤어·옷을 레이어로 나누는 것은 허용한다.
- 게임용 내보내기는 **완성된 캐릭터 프레임**이다. 파츠별 런타임 조립이나 조합별 호환성 검수는 요구하지 않는다.
- 스타일별 얼굴·피부색·헤어색·의상·신발은 디자인에 포함하여 고정한다. 독립 색상 변경 메뉴나 피부 팔레트 5종 제작을 의무화하지 않는다.
- 모자·가방·장식도 스타일에 포함한다. 개별 탈착 슬롯은 없다.
- 장식이 커도 발바닥 기준점과 충돌 크기는 공통 플레이 기준을 따른다. 의상별로 이동 유불리가 생기지 않도록 검증한다.
- 이미지 생성·편집 전 아트 가이드와 본 문서, 연결된 참고 이미지를 확인한다.

## 4. 방향과 애니메이션

선택창의 정면 정지 미리보기와 월드에서 사용할 스프라이트의 완료 상태를 구분한다.

| 용도 | 필요 범위 | 상태 기준 |
| :--- | :--- | :--- |
| 선택창·상점 미리보기 | 정면 `down/idle` 1프레임부터 검증 | 외형 후보 확인용. 이것만으로 월드 적용 완료라 표시하지 않음 |
| 월드 적용 | `down/up/left/right` 정지와 걷기 | 실제 지원 동작을 모두 제작·검수한 스타일만 적용 |
| 앉기·운반·작업 | 실제 게임 동작에 맞춰 추가 | 지원 범위와 대체 동작은 구현 전 결정 |

방향당 정지 1 + 걷기 4프레임은 **검증용 제안**이다. 채택하면 스타일당 20개 프레임 위치가 필요하다. 스타일 4종으로 시작한다면 80개 위치가 필요하므로 완성형 전환이 애니메이션 제작량까지 없애는 것은 아니다. 초기 4종은 권장 시작 규모이며 출시 수량 확정은 아니다.

모든 스타일은 동일한 캔버스 크기·접지점·프레임 순서·재생 시간 기준을 공유한다. 투명 여백을 개별 삭제하지 않는다. 대칭 디자인만 좌우 반전 재사용을 허용한다. 비대칭 장식은 별도 방향을 제작한다.

## 5. 파일 및 데이터 명세

다음은 예정 구조이며 실제 구현 파일이 아니다.

```text
characters/player/styles/{styleId}/
  source/{styleId}.aseprite
  preview.png
  idle_down.png
  idle_up.png
  idle_left.png
  idle_right.png
  walk_down.png
  walk_up.png
  walk_left.png
  walk_right.png
  manifest.json
```

정지는 완성형 단일 프레임, 걷기는 완성형 프레임을 같은 크기 셀에 순서대로 배치한 시트다. 투명 PNG RGBA, 선명한 픽셀 경계를 사용한다. 64×64는 검증 후보이며 생성 이미지 크기를 그대로 런타임 규격으로 확정하지 않는다.

메타데이터에는 `styleId`, 표시 이름, 설명, 미리보기 경로, 방향·동작별 이미지, 프레임 수·시간, 공통 캔버스·접지점, 템플릿 버전, 지원 동작, 제작·검수 상태를 기록한다. 보유와 착용 데이터는 `ownedStyleIds`, `equippedStyleId` 같은 스타일 단위로 설계한다. 얼굴·헤어·신발 장착 ID를 새 외형 선택 계약에 포함하지 않는다.

## 6. 제작 순서와 완료 기준

1. 정면 완성형 후보 소수로 그림 밀도·비율·스타일 구분을 검증한다.
2. 대표 1종의 4방향·걷기로 공통 동작과 좌표를 확정한다.
3. 같은 템플릿으로 나머지 스타일을 제작한다.
4. 선택창·상점·옷장 미리보기와 실제 월드 외형이 일치하는지 확인한다.

- [ ] 각 스타일이 헤어·옷·색·실루엣으로 구분된다.
- [ ] 독립 파츠 선택을 요구하지 않고 한 `styleId`로 외형 전체가 바뀐다.
- [ ] 모든 필수 방향·동작이 존재하고 발바닥 위치와 움직임이 일관된다.
- [ ] 피부·장식 포함 전체 외형이 미리보기와 일치한다.
- [ ] 교체 시 플레이어 진행 데이터가 유지된다.
- [ ] 그림의 장식 크기 때문에 충돌·이동에 차이가 생기지 않는다.
- [ ] 생성 이미지, 제작 완료 에셋, 월드 적용 검수를 구분해 기록했다.

## 7. 이전 방식에서의 전환

기존 파츠 에셋은 디자인 자료로 활용할 수 있으나, 무조건 삭제하거나 완성형 제작 완료로 간주하지 않는다. 실제 코드·저장 데이터에 파츠 보유 정보가 있다면 별도로 조사하고 스타일 매핑 및 보상 여부를 정한다. 이번 문서 개정에서 기존 소유 데이터를 임의로 변환하지 않는다.
