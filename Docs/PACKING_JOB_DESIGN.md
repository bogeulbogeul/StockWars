# 비비안 잡화점 포장 알바 기획 정리

**2026-10-26 보상 전달 후속 — 구현 전:** 전시 포장 3상자를 마치면 봉봉이 보수 300잎과 함께 누군지 모르는 사람이 남긴 소식봉투를 건넨다. 발신자의 정체는 밝히지 않으며 두 보상은 중복 지급하지 않는다. 대사는 [최신 전시 구성](EXHIBITION_SHORT_DEMO_2026-10-26.md)을 따른다.

[최신 전시 구성·대사](EXHIBITION_SHORT_DEMO_2026-10-26.md)를 따른다. 아래 5상자·기존 보수·패턴 배분은 기존 시제품 기록이다. 일반 모드 변경·새 3상자의 난이도 배분 변경은 별도로 확정하지 않았다. 이번 문서 갱신은 게임 코드 적용이나 완료 판정 검증을 의미하지 않는다.

2026-10-24 명칭 통일: **별가루(+1·500잎)·달가루(찌라시 한 건 분석력 MAX 기준 해석·2,000잎)**를 사용한다. 반짝가루는 이전 명칭이며 [현행 상품 명세](MOD_GDD_03_1_VivianStore.md)를 따른다. 포장용 공급·점유 칸·제작 원본·내부 키는 변경하지 않는다.


작성일: 2026-10-21 / 최종 갱신: 2026-10-22. 이 대화에서 정한 규칙, 현재 웹 시제품, 완료 후 보수·봉투 전달 연출을 구분해 기록한다. 노동 전체 명세는 [노동 시스템](MOD_GDD_02_LaborJobs.md)을 따른다.

## 1. 게임의 핵심

잡화점에서 판매하는 상품을 상자에 빈틈없이 담는 2D 공간 퍼즐이다. 음식 조립이나 진열대에서 주문 상품을 찾는 방식 대신, 이번 상자에 필요한 상품을 모두 제공한다. 플레이어는 상품의 위치를 조합하는 데 집중한다.

- 화남 게이지·시간제한·손님 대기 취소 없음.
- 난이도 선택 없이 한 게임에서 서로 다른 상자가 무작위로 등장.
- 회전 기능 없음. 그림과 점유 칸은 상품의 기본 방향으로 고정.
- 모든 상품을 담고 모든 칸을 채워야 완료. 겹침과 상자 밖 배치는 불가.
- 준비된 예시 정답 외에도 조건을 만족하는 모든 배치를 인정.

## 2. 플레이 흐름과 패턴

알바 시작 → 상자와 필요한 상품 제공 → 드래그로 배치·수정 → 포장 완료 → 다음 상자 → 목표 달성 후 결과 화면.

현재 시제품은 **20개 패턴 중 중복 없이 5상자**를 제공한다. 16칸 이하 상자 3개와 20칸 상자 2개를 뽑아 순서를 섞으며, 난이도가 순차 상승하는 구조는 아니다. 5상자는 현재 플레이 검증용 목표값으로, 최종 노동량·보상 균형은 별도 조정 대상이다.

상자 종류는 가로×세로 기준 3×3, 3×4, 4×3, 4×4, 5×3, 3×5, 5×4, 4×5다. 같은 크기도 상품 구성이 다르며, 20개 모두 회전 없이 완전히 채울 수 있다. 정확한 상품 구성과 해답은 [패턴 데이터](../web/js/components/packing/PackingData.js)에 보관한다.

## 3. 상품과 점유 칸

상품별 실제 파일·포장 표현·상자/UI·보수 전달 소품의 제작 상태는 [잡화점 포장 에셋 명세](SHOP_PACKING_ASSET_GUIDE.md)에 통합했다. 2026-10-22 코드·파일 대조 기준이며 기존 시안과 현행 포장용 에셋을 구분한다.

| 상품 | 가로×세로 | 표시 방향 |
| --- | --- | --- |
| 꿀 쿠키 | 2×2 | 정방형 쿠키 포장 |
| 꽃잎 차 | 2×2 | 세워진 상품 포장 |
| 사과 주스 | 1×3 | 세로로 긴 병 |
| 포포리빵 | 3×1 | 가로로 긴 통빵 |
| 꽃꿀 베리 주스 | 1×2 | 세워진 병 |
| 허브 차 | 2×1 | 가로로 긴 차 상자 |
| 별가루 | 1×1 | 정방형 한 칸 |
| 달가루 | 1×1 | 정방형 한 칸 |
| 이슬 젤리 | 1×1 | 정방형 한 칸 |
| 꽃꿀 사탕 | 2×1 | 양쪽 포장지가 있는 가로형 |

도토리빵은 포포리빵으로 변경했다. 포포리빵은 단면 없는 주황빛 통빵과 꽃·잎무늬 크림 종이 포장을 사용한다. 상품 그림은 준비 공간·드래그 중·상자 안에서 같은 방향을 유지하며, 병을 눕히거나 빵을 세워 해답에 맞추지 않는다.

**2026-10-22 표시 복구:** 현재 탭에서 포포리빵이 깨진 이미지로 표시되는 것을 확인했다. [통빵 원본 PNG](../web/assets/items/packing-v1/popori-bread-v2.png)는 정상이었으며 로컬 서버 연결 거부도 확인했다. 서버를 다시 실행하고 이미지 및 관련 화면/입력 모듈에 새 버전 주소(`whole-loaf-20261022`)를 연결한 뒤, 현재 독립 플레이 화면에서 정상 표시를 확인했다. 이미지 재생성이나 새 외형 채택이 아니라 기존 선택 이미지의 로딩 복구다. 준비 공간·드래그·상자 안은 같은 `artHtml` 경로를 사용한다. 설치 프로그램 재배포 검증과는 별개다.

## 4. 화면과 조작

- 한 화면에 제목, 완료 수, 상자, 담을 물건, 조작 버튼을 표시한다. 작은 화면에서는 위아래 배치로 조정한다.
- 상자는 꽃·잎무늬와 접힌 종이 테두리가 있는 [상자 PNG](../web/assets/items/packing-v1/packing-box-v1.png)를 사용한다. 실제 격자는 상자 크기에 맞춰 표시한다.
- 상품 그림 영역을 잡아 끈다. 이름·카드 외곽 여백은 드래그 시작 영역에서 제외한다. 작은 그림에는 잡기 여유를 둔다.
- 잡으면 바로 이동 그림을 표시하고 상자 위에서는 배치 가능 여부를 미리 보여준다. 불가능한 곳에 놓으면 원래 위치를 유지한다.
- 상자에 담은 상품은 다시 옮기거나 준비 공간으로 끌어 꺼낼 수 있다.
- **모두 꺼내기:** 상자의 상품 전체를 준비 공간으로 반환한다. 빈 상자에서는 비활성화한다.
- 같은 상품이 여러 개면 준비 공간에서 한 묶음으로 표시하고 그림 위에 **×2** 등 수량 배지를 붙인다. 하나씩 독립적으로 담으며, 1개 남으면 배지는 사라진다.
- 보조 조작으로 상품 선택 후 칸 클릭·키보드 입력을 지원한다. 회전 버튼과 R키 기능은 없다.
- 처음 잡을 때 포커스·포인터 캡처가 바뀌어도 드래그를 유지하도록 보완했다. 실제 취소·화면 숨김·종료 시에는 정리한다. 자동 테스트 통과와 사용자 체감 검수는 구분한다.

## 5. 알바 완료와 돈주머니·찌라시 봉투

### 최신 사용자 제안: 포장 UI를 닫고 봉봉이 보수 전달 — 2026-10-22

사용자는 포장 UI를 닫은 뒤 **봉봉이 돈주머니를 건네는 방식**을 제안하고, 돈주머니 디자인 제작을 요청했다. 결과 창 안에 보수·봉투를 모두 표시하는 아래 이전 제안보다 이 방향을 우선해 후속 설계한다. 현재 웹 시제품에는 아직 적용하지 않았다.

연출 흐름 초안:

1. 마지막 상자의 포장 완료 후 포장 UI를 닫는다.
2. 잡화점에서 봉봉과 마주 보는 장면으로 이어진다. 정확한 카메라·캐릭터 위치는 미정.
3. 봉봉이 돈주머니를 건넨다. 대사 후보: “고생했어! 오늘 일한 몫이야.”
4. 돈주머니 수령 시 `+○○잎`과 동전 효과로 보수를 표시한다. 보수 액수·정산 시점·중복 지급 방지 구현은 미정.
5. 봉투 지급 조건을 충족한 경우, “아, 잠깐! 아까 어떤 손님이 이것도 전해 달라고 하더라.”라는 대사와 함께 찌라시 봉투를 별도로 전달한다.
6. 대화 종료 후 자유 행동으로 돌아간다. 첫날 정보 해석 안내와의 연결은 별도 설계한다.

돈주머니를 수령 연출 뒤 사라지는 소품으로 두고 보유 금액에 반영하는 방식은 제안이다. 실제 인벤토리 아이템 여부는 확정하지 않았다. 봉투의 ‘지금 열어보기 / 나중에 보기’와 수령 즉시 보관도 제안이며 지급 조건·저장 계약은 미정이다.

### 돈주머니 디자인 요청과 제작 상태

- **사용자 지정:** 갈색 복주머니, 앞면에 마을 상징 새싹 문양.
- **디자인 제안:** 통통한 천 주머니, 베이지색 매듭끈, 연두색 새싹. 색조·재질·매듭 세부는 아직 최종 채택 전이다.
- **제작 상태: ⏳ 대기.** 이미지 생성·게임 적용은 하지 않았다. 현재 안내소 새싹 마크 및 은행 마크의 참고 PNG가 Git LFS 포인터만 있는 상태로 열리지 않았다. 원본 가져오기도 인증 문제로 완료하지 못했다. 원본 문양 이미지 확보 후 형태를 확인해 제작한다.
- 참고 문양을 기억이나 다른 새싹으로 대체하지 않는다. 사용자에게 문양 이미지 또는 해당 화면 첨부를 요청한 상태이며, 이번 문서 갱신으로 새 상징을 확정하지 않는다.

### 찌라시 봉투 전달 설정

알바가 끝난 뒤 봉봉이 **“아까 어떤 손님이 전해 달라고 부탁했다”**며 찌라시가 든 봉투를 건넨다. 직접 들은 소문을 말로 전달하는 안보다, 손님이 맡긴 봉투를 대신 전해 주는 방향으로 논의했다. 대화 초기에 사용한 비비안 표기는 이 절의 최신 전달자 봉봉으로 정리한다.

발신자의 정체·이름 공개 여부·플레이어를 아는 이유는 아직 정하지 않았다. 이전 ‘수상한 손님이 직접 주문하고 성공 보상으로 지급’ 설정과의 관계도 후속 정리가 필요하다. 이번 연출 논의만으로 매번 지급·확률 지급·첫 보장 지급 등의 조건을 확정하지 않는다.

### 이전 완료 UI 제안 — 이력 보존·미구현

아래는 포장 결과 창 안에서 보수와 봉투를 함께 보여주는 이전 제안이다. 최신 후속은 포장 UI를 닫고 봉봉이 직접 전달하는 위 흐름이며, 아래 내용을 현행 확정 UI로 구현하지 않는다.

1. 마지막 상자 완료 후 **오늘의 포장 완료! / 5상자를 모두 포장했어요.** 표시.
2. 같은 결과 창에서 받은 보수 표시. 단위는 **잎**, 액수는 미정.
3. 비비안의 전달 대사와 봉인된 봉투 표시.
4. **봉투 열기**를 누르면 같은 창에서 봉인이 풀리고 쪽지가 펼쳐짐.
5. 소문 제목·내용을 읽은 후 보관 안내와 **마을로 돌아가기** 표시.

대사 초안: “아, 맞다! 아까 어떤 손님이 이걸 너한테 전해 달라고 하더라.”

후속 대사 후보: “네 앞으로 또 봉투가 왔어.”

아래 요소는 대화 중 제안이며 확정 사항이 아니다.

- 봉투 겉면에 ‘받는 이: 플레이어 이름’ 표시.
- ‘이름은 안 남기고 갔어’라는 대사와 익명 발신자 설정.
- 짧은 개봉 애니메이션과 클릭으로 연출 건너뛰기.
- 쪽지에 ‘익명의 제보 · 사실 여부 미확인’ 표기. 정보는 확정 수익이나 예언이 아닌 판단할 소문·단서로 표현.
- 정보 수첩에 자동 보관. 기존 소지품·찌라시 해석 기능과의 저장/열람 연결은 미정이며 별도 수첩 구현을 완료한 것으로 취급하지 않는다.

봉투가 지급되지 않는 회차의 완료 UI, 바로 열지 않고 나중에 여는 기능, 개봉 전후 재진입 동작도 후속 설계 대상이다.

| P1 (Major) | 갈색 새싹 복주머니 디자인 | ⏳ 대기: 마을 문양 원본 확보·시안 제작·검수 |
| P0 (Core) | 중복 보상 방지·봉투/정보 저장·첫날 연결 | ⏳ 대기: 저장 계약·구현·검수 |

현재 실행 중 나갔다 돌아오면 진행을 유지한다. 새로고침·앱 종료를 넘는 저장은 없다. 현재 결과 화면은 완료 수·다시 하기·나가기이며 보수나 봉투를 지급하지 않는다. 미니게임은 개인 보유품·재화·하트도 차감하지 않는다.

첫날의 기존 찌라시 해석 학습 목적은 유지한다. 첫 체험의 상자 수·보장 지급 방식과 새 봉투 연출을 연결할 때 기존 안내용 보상을 중복 지급하지 않도록 설계한다. 폐기한 물류·박씨 노동·화남 게이지·회전을 복원하지 않는다.
