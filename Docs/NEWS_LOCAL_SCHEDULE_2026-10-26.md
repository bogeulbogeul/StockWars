# 소식 앱 로컬시간 정기 발행

**P1 (Major) · ✅ 완료: 웹·기존 실행본 리소스 적용·자동 검증 / ⏳ 대기: 사용자 최종 플레이 검수.**

사용자 확정: **기기 로컬시간 매일 09:00·12:00·15:00·18:00·21:00에 무작위 뉴스 1건씩 발행한다.** 한국시간으로 고정하지 않는다. 이전의 288건 전체 초기 공개와 이번 대화에서 제안했던 분 단위 간격보다 이 확정 시간을 우선한다.

## 발행·표시

- `ScheduledNews.js`가 다음 로컬 달력 시각을 계산하고 `ScheduledNewsRuntime.js`가 발행·저장·화면 구독을 맡는다. 일반/첫날 전시의 `PhoneStockSource.js`가 같은 정책으로 소식 앱에 공개된 기사만 전달한다. 기존 500줄 초과 시장 엔진에는 기능을 덧붙이지 않았다.
- 첫 이용에서는 당일 이미 지난 시간대의 기사만 생성한다. 예를 들어 로컬 14시에 처음 열면 09시·12시 기사 2건이 보인다. 미래 기사나 원고 288건 전체를 미리 노출하지 않는다.
- 일반 모드는 별도 `stockwars-scheduled-news-v1` 키에 발행 이력·남은 추첨 풀·처리 시점을 저장한다. 재접속·숨긴 창 복귀 시 지난 슬롯을 한 번씩 반영하며 원래 예정 시각으로 표시한다. 저장 공간 사용이 불가하면 현재 세션에서만 유지한다.
- 첫날 전시는 기존 초기화 정책에 맞춰 새로고침하면 별도 새 세션으로 시작한다. 당일 지난 슬롯을 다시 생성하며 일반 모드의 발행 이력을 읽거나 바꾸지 않는다. 전시 내 앱 닫기/재열기에서는 같은 이력을 유지한다.
- 매번 남은 원고에서 균등 무작위 추첨한다. 288건을 모두 사용하면 새 추첨 주기를 시작한다. 화면 이력은 최신 288건을 유지하며 발행 건별 ID로 기사를 구분한다.
- 최신 기사부터 정렬하고 기사에 실제 로컬 발행 날짜·시각을 표시한다. 새 기사가 들어와도 읽던 기사와 본문 스크롤을 유지한다.
- 로컬 날짜 생성으로 자정과 일광절약시간 전환을 처리한다. 일반적인 시계 역행은 처리 커서를 되돌리지 않아 같은 슬롯을 재발행하지 않는다. 클라이언트 기기 시계에 의존하는 로컬 기능이며 서버 공통 뉴스·전 세계 동일 추첨·시계 변조 방어를 구현한 것은 아니다.
- 기존 원고·회사 연결·주가 계산·보상·계좌·스토리 저장은 유지한다. 뉴스 분류를 주가 변동이나 찌라시 진위로 자동 연결하지 않는다.

## 검증

- 발행 시간 경계·정시 중복·당일 첫 이용·오프라인 경과·재접속 이력·시계 역행·288건 비반복 추첨·원문 보존·잘못된 저장 검사 7개 통과.
- 스마트폰 지도·업적·내 정보·할 일 회귀를 포함해 17개 테스트 통과.
- 실제 Chrome의 `Asia/Seoul`·`America/New_York`에서 일반/전시 4가지 조합을 검사했다. 08:59:59에는 빈 목록, 09시에는 1건, 12시에는 2건이 자동 표시되고 기사 열람 중 새 발행 후에도 읽던 기사를 유지했다. 일반 재접속 기사 ID 일치와 DST 전환일의 다섯 로컬 시각을 확인했다. 양쪽 리소스에서 JavaScript 예외 0건이다.
- 기존 실행본 `electron-app/dist/win-unpacked/resources/web/`에 변경 모듈 4개를 동기화하고 SHA-256을 대조했다. 설치 프로그램 재빌드·Electron 직접 실행·사용자 최종 검수는 별도다. 실행 중인 게임은 재실행해야 반영된다.
