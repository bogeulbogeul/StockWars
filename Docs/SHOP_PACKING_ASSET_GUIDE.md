# 잡화점 에셋 — 포장 알바 기준

## 상품 이미지 현행 적용 기준 — 2026-10-24

**P1 (Major) · ✅ 실제 참조·웹/로컬 실행본 대조·문서 정리.** 상품 12종의 현재 외형·파일·시트 영역은 [잡화점 상품 이미지 현황](SHOP_ITEM_IMAGE_STATUS.md)을 따른다. 현재 상점·상품 상세·가방은 포장 PNG 영역과 개별 PNG를 공통으로 표시한다. 2026-10-25 사용자 요청으로 **연두색 가로 로또·종이가 보이지 않는 닫힌 크림색 봉투 v4를 적용**했다. 초록 잎 문양 봉인과 기존 시안 외형을 유지한다. 웹·로컬 실행본의 상점·가방·로또 화면에 같은 이미지를 연결했다. 아래 과거 제작 대기·시안 설명과 실제 적용 상태를 구분한다. 상품 이미지는 v4로 교체했으며 판매용 네이티브 3D 모델 제작 완료를 뜻하지 않는다.


2026-10-24 명칭 통일: **별가루(+1·500잎)·달가루(찌라시 한 건 분석력 MAX 기준 해석·2,000잎)**를 사용한다. 반짝가루는 이전 명칭이며 [현행 상품 명세](MOD_GDD_03_1_VivianStore.md)를 따른다. 포장용 공급·점유 칸·제작 원본·내부 키는 변경하지 않는다.


2026-10-22 정리. **P1 (Major) · ✅ 완료: 현행 데이터·표시 코드·파일 대조 및 문서 정리 / ⏳ 대기: 최종 아트·플레이 검수, 후속 전달 소품 제작.**

## 1. 적용 범위

봉봉의 잡화점 포장 알바에 필요한 상품·상자·화면·보수 전달 소품을 기준으로 관리한다. 플레이 규칙은 [포장 알바 통합 기획](PACKING_JOB_DESIGN.md)이 기준이다. 여기서 포장물류는 현재 잡화점 포장 퍼즐을 뜻한다. 폐기된 비트 물류창고·박씨·퀵패스·서브 퀘스트·칭호는 제작 목록에 포함하지 않는다.

현재는 필요한 상품을 미리 제공하고, **기본 방향 그대로 회전 없이 빈칸을 모두 채우는 2D 퍼즐**이다. 20개 패턴에서 중복 없는 5상자(작은 상자 3개·큰 상자 2개)를 제공한다. 상품 판매·개인 소지품과 포장용 공급은 별개다.

## 2. 포장 상품 10종

판매 가격은 [잡화점 가격 초안](MOD_GDD_03_1_VivianStore.md#개편-상품-가격-초안--2026-10-22)을 따른다. 꿀 쿠키 4개입 세트 800잎(2026-10-24 확정·적용)·나머지 회복 먹거리 7종 각 200잎·별가루 500잎·달가루 2,000잎이다. 별가루는 지정 찌라시 한 건의 해석 단계 +1, 달가루는 지정 한 건을 분석력 MAX 기준으로 해석한다. 플레이어 분석력·다른 찌라시·소문의 진위는 바꾸지 않는다. 꿀 쿠키는 세트로 보관하고 하나씩 꺼내 먹을 때 하트 1칸을 회복한다. 가격의 경제 균형 검증은 별도이며 점유 칸 크기와 연동하지 않는다. 포장용 제공 상품에 구매 비용을 부과하는 변경이 아니다.

크기는 **가로×세로 점유 칸**이며 이미지 픽셀 크기가 아니다. A~K는 포장 데이터의 키로 판매·인벤토리 ID와 구분한다.

| 키 | 상품 | 점유 칸 | 포장용 표현 | 현재 소스 |
| --- | --- | --- | --- | --- |
| A | 꿀 쿠키 | 2×2 | 정방형 쿠키 포장 | 공통 시트 art 0 |
| B | 꽃잎 차 | 2×2 | 닫힌 세로형 상품 포장 | 공통 시트 art 1 |
| C | 사과 주스 | 1×3 | 세워진 긴 병 | 공통 시트 art 2 |
| D | 포포리빵 | 3×1 | 가로 통빵·꽃/잎무늬 크림 종이 포장, 단면 없음 | 개별 PNG |
| E | 꽃꿀 베리 주스 | 1×2 | 세워진 병 | 공통 시트 art 4 |
| F | 허브 차 | 2×1 | 닫힌 가로형 차 상자 | 공통 시트 art 5 |
| G | 별가루 | 1×1 | 가루 상품 포장 | 공통 시트 art 6 |
| H | 달가루 | 1×1 | 별가루와 구별되는 가루 상품 포장 | 공통 시트 art 7 |
| I / K | 이슬 젤리 | 1×1 | 한 칸 젤리 상품 | 공통 시트 art 8 공유 |
| J | 꽃꿀 사탕 | 2×1 | 양쪽 포장지가 있는 가로형 | 공통 시트 art 9 |

K는 별도 상품이 아니라 같은 젤리를 독립적으로 담기 위한 인스턴스다. **상품 종류는 10종**이다. 10종은 현재 포장 퍼즐 구성이지 전체 판매 목록을 10종으로 확정하는 결정이 아니다.

- [공통 상품 시트](../web/assets/items/packing-v1/items.png): `PackingView.js`의 `ART_REGIONS`로 원본의 표시 영역을 나눈다. 포포리빵의 이전 art 3 영역은 현행 빵 표시에서 사용하지 않는다.
- [현행 포포리 통빵](../web/assets/items/packing-v1/popori-bread-v2.png): D는 개별 PNG를 사용한다. 주황색·파파야형 열매잼이라는 상품 설정은 유지하되 포장 조각은 단면을 노출하지 않는다.
- 기준 코드: [PackingData.js](../web/js/components/packing/PackingData.js), [PackingView.js](../web/js/components/packing/PackingView.js). 준비 공간·드래그·상자 안에서 같은 `artHtml`을 사용한다.

## 3. 상자와 화면 에셋

| 요소 | 현재 방식·상태 | 제작·관리 기준 |
| --- | --- | --- |
| 포장 상자 | [상자 PNG](../web/assets/items/packing-v1/packing-box-v1.png) 연결 | 꽃·잎무늬·접힌 종이 테두리, 격자와 구분 |
| 상자 격자·배치 미리보기 | DOM/CSS 구현 | 실제 칸·충돌 판정과 일치, 이미지에 고정 숫자나 격자를 굽지 않음 |
| 상품 준비 공간·수량 배지 | DOM 구현 | 같은 상품을 묶고 ×2 등 수량 표시, 조각은 하나씩 배치 |
| 작업대·완료 수·버튼·선택 상태 | DOM/CSS 구현 | ‘모두 꺼내기’·‘포장 완료’·종료, 화면 크기 대응 |
| 현행 결과 화면 | 완료 수·다시 하기·나가기 구현 | 보수·봉투 지급이 구현된 화면으로 기록하지 않음 |

상자 크기는 3×3, 3×4, 4×3, 4×4, 5×3, 3×5, 5×4, 4×5다. 크기마다 별도 완성 화면 이미지를 만들지 않고 상자 아트와 가변 격자를 함께 사용한다. 회전 버튼·화남 게이지·타이머·고정 진열대 주문 찾기 화면은 현행 제작 목록에서 제외한다.

## 4. 알바 종료 후 전달 소품

| 소품·장면 | 방향 | 상태 |
| --- | --- | --- |
| 돈주머니 | 봉봉이 전달하는 갈색 복주머니·마을 새싹 문양 | ⏳ 참고 문양 원본 확보·제작·검수 대기 |
| 찌라시 봉투 | 조건 충족 시 봉봉이 손님에게 맡은 봉투 전달 | ⏳ 지급 조건·전달/개봉·저장 설계 및 구현 대기 |
| 보수 표시 | 돈주머니 수령과 함께 +○○잎 | ⏳ 액수·정산 시점·중복 지급 방지·연출 구현 대기 |

최신 방향은 **포장 UI 종료 → 봉봉의 돈주머니 전달 → 조건 충족 시 찌라시 봉투 전달**이다. 돈주머니는 인벤토리 보유 아이템으로 아직 확정하지 않았다. 봉투와 주간 로또는 현재 10종 포장 조각에 포함하지 않으며, 봉투 전달 소품과 판매용 정보 상품의 에셋 재사용 여부도 후속 결정이다. 새싹 원본을 다른 문양으로 임의 대체하지 않는다.

## 5. 판매·인벤토리·이전 시안의 관계

- **판매 UI:** 3D 상품 표현 방향 유지. 현재 포장 PNG의 연결이 판매용 3D 모델 제작 완료를 뜻하지 않는다.
- **인벤토리:** 간결한 2D 아이콘 방향 유지. 포장 아트를 참고하되 아이콘 크기·여백·수량 표기에서 식별성을 따로 검수한다. 포장 코드의 키를 기존 보유품 ID로 자동 이관하지 않는다.
- **이전 12종 모음:** [시안 v1](../output/vivian-items-2d-concept-v1/overview.png)은 외형 탐색 이력이다. 찻잔·도토리빵을 현행 포장 입력으로 다시 사용하지 않는다.
- **포포리빵 전체·단면:** [2D 시안 v2](../output/popori-bread-2d-v2/overview.png)는 잼·상품 컨셉 참고다. 현행 포장용은 위 개별 통빵 PNG다.
- [제작 기록](../output/packing-ui-v1/README.md)의 과거 회전·10패턴·CSS 상자 설명보다 현재 통합 기획과 실행 코드를 우선한다.

## 6. 후속 작업과 검수

1. **P0 (Core):** 기본 방향·점유 칸 유지, 20패턴 완전 채움, 준비 공간→드래그→상자 안의 이미지 일치 검수. 크기 변경 시 패턴 검증도 함께 갱신한다.
2. **P1 (Major):** 작은 화면의 포장지·상품 실루엣·수량 식별, 이미지 로딩과 가장자리 잘림 검수. 시안의 자세한 질감을 그대로 최종 아이콘 규격으로 확정하지 않는다.
3. **P1 (Major):** 돈주머니 원본 문양 확보 및 소품 제작, 봉투 전달 장면과 지급·저장 계약 설계.
4. **P1 (Major):** 판매 3D와 인벤토리 2D의 동일 상품 외형 연결 및 최종 사용자 검수.

이번 정리는 파일 존재와 데이터·표시 참조를 확인한 문서 작업이다. 이미지를 재생성하거나 이동·삭제하지 않았으며 브라우저·배포 검증을 새로 수행한 기록이 아니다. 기존 검증 범위는 [통합 기획 7절](PACKING_JOB_DESIGN.md#7-실행검증-참고)을 따른다.
