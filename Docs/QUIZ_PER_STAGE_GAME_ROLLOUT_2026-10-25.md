## 단계별 문항

각 사건의 해석 1~5단계마다 서로 다른 문항을 하나씩 준비했다. 같은 단계에서 재접속·재열람하면 같은 문항을 사용하고, 실제 표시 단계가 달라지면 그 단계 문항 하나만 출제한다. 다섯 문항을 연속으로 풀도록 요구하지 않는다. 가루나 임시 분석력 효과가 기본 분석력보다 더 높은 해석을 열면 그때 실제 표시된 단계 문항을 따른다.

| 단계 | 확인할 해석 |
|---|---|
| 1 | 비유 속 사건과 제약을 읽는다. |
| 2 | 회사와 사건의 핵심 주장·확인 과제를 파악한다. |
| 3 | 성사·대응 조건과 진행 중·미확정인 현재 상태를 함께 구분한다. |
| 4 | 출처의 관계와 한계, 적용 범위·경쟁·대안을 읽는다. |
| 5 | 예정된 확인 시점과 아직 모르는 수치·결과를 나눠 판단한다. |

기존 1·2·4단계용 864문항을 유지하고 3·5단계 576문항을 추가했다. 추가 문항은 사건별 실제 본문의 조건·현재 상태 또는 마지막 시점·정보 한계 문장을 근거로 구성했다. 질문·보기 3개·정답·해설·해당 단계 원문 근거를 회사별로 기록했다. 브리즈파워 공급 계약설은 사용자가 채택한 1~5단계 예시 문항으로 모두 교체했다. 같은 사건의 다섯 질문이 서로 다른지와 원고·런타임 일치를 검증했다.

회사별 문서는 4개 사건·20문항이고 전체는 288개 사건·1,440문항이다. [현행 원고 목록](RumorQuizzes/README.md)을 따른다. 이전 3구간 문항 원고는 `Docs/Archive/RumorQuizzes_ThreeBands_2026-10-25/`에 회사별로 보관했다. 찌라시 본문 1,440개와 퀴즈 1,440개는 서로 다른 데이터이며 우연히 수량이 같다.

## 보상·저장

사건당 정답 숙련도 +1·플레이어별 한 번 지급·오답 후 재도전 동일 보상을 유지한다. 지급 기준은 문항 ID가 아니라 기존 `rumorId`다. 다른 단계의 새 문제, 사본·선물·재구매·재접속 모두 같은 사건의 지급 이력을 공유한다. 이미 보상받은 사건은 새 3·5단계 문제를 맞혀도 +0이다. 최대 Lv.5의 무보상 복습도 유지한다.

분석력 단계·숙련도·성장 요구량 20·30·40·60·누적 정답 150개, 가루 해석 이관·개별 단계, 보유 원고·가격·수량은 변경하지 않았다. 기존 `analysisGrowth.awarded`와 시각·지급량을 수정하거나 초기화하지 않는다. 문항 키를 `authored-five-v2`로 갱신해 이전 구간형 세션의 제출은 재열람을 안내하고, 다시 문제를 열 때 현재 단계의 문항 세션만 바꾼다. 새 세션의 오답 재도전·재접속은 기존 저장 흐름을 따른다.
