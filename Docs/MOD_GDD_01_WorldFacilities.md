# StockWars GDD: MOD_GDD_01. 타운 시설 및 월드 구성

## 플레이어 집의 임대 배경 — 2026-10-21 사용자 채택

플레이어가 입주하는 집은 **이전에 살던 집주인이 세를 내놓고 세계여행을 떠난 집**이다. 소망이는 포포리 마을에 정착하며 이 집을 빌려 살고, 집주인은 여행으로 부재 중이다. ‘이전 주인’은 이전 거주자이자 현재 임대인이라는 뜻이며 소유권을 소망이에게 넘긴 설정은 아니다.

모아가 마을과 빈 집을 소개할 때 이 배경을 짧게 알려준다. 기존 입주·월세·집꾸미기 흐름을 유지하며 기존 집 모델·룸·가구를 자동 변경하지 않는다. 임대인의 이름·외형·구체 여행지·귀환 시점은 아직 정하지 않는다. 소망이의 출생이나 도입의 씨앗·편지의 발신자와도 연결을 확정하지 않는다.

**2026-10-21 여행 우편 후속 채택:** 집주인은 세계여행 중 **가끔 편지나 기념품을 보내준다.** 편지에는 여행지에서 만난 풍경·사람·소소한 경험과 소망이의 안부를 담으며, 기념품이 함께 도착할 수도 있다. 소망이는 **집 앞 우편함**에서 편지를 읽고 첨부된 기념품을 받는다. 여행 중인 집주인이 일상 속에서 느슨하게 이어지는 관계로 설정한다. 발송 주기·첫 도착 시점·구체 여행지·기념품 종류/수량·효과·답장 조건은 후속 설계한다. [우편 기획](MOD_GDD_09_FriendSystem.md)을 따른다.

**P1 (Major) · ✅ 완료: 주거 배경 기획 반영 / ⏳ 대기: 소개 대사 게임 적용·검수.** 첫 월세 5,000잎과 정착 대출은 기존 조건을 유지하며 별도 보증금·새 요금·퇴거 조건은 추가하지 않는다.

## 마을 이름 확정 — 2026-10-21 사용자 채택

정식 명칭은 **포포리 마을**, 주민 대화에서 사용하는 줄임말은 **포포리**로 확정한다. 모아·봉봉·우디·토리·차곡·도란·보니·소담·두리가 살아가는 요정 마을의 지명이다. 간판·지도·정류장·입주 신청서 등 장소를 정식으로 안내할 때는 ‘포포리 마을’을, 일상 대화에서는 ‘포포리’를 사용할 수 있다.

현재 개인 마을의 생활·정착 공간을 가리키며, 공용 만남 광장은 기존 별도 공간으로 유지한다. 플레이어별 마을 이름 입력·개명 기능이나 공용 광장의 새 고유 이름은 추가하지 않는다. 게임·프로젝트 이름은 **StockWars**를 유지한다.

**P1 (Major) · ✅ 완료: 지명 채택·문서 반영 / ⏳ 대기: 게임 표시·도입 대사 적용·검수.** 기존 에셋·파일 경로·내부 ID·저장 키는 변경하지 않는다.

## 마을 중앙 세계수 이름 확정 — 2026-10-21 사용자 채택

포포리 마을 중앙에 있는 세계수의 고유 이름은 **포포리 나무**로 확정한다. 주민 대화·지도·장소 안내에서는 이 이름을 사용하며, 기존 제작 기록의 ‘세계수’·‘중앙 나무’는 해당 나무를 가리키는 설명으로 유지한다. 예: “포포리 나무 앞에서 만나요.”

개인 마을 중앙의 나무에 붙인 이름이며 아래 공용 만남 광장의 ‘작은 소망 나무’를 함께 개명하는 결정은 아니다. 외형·모델·배치와 성장·보상 기능은 이번 명명으로 변경하지 않는다.

**P1 (Major) · ✅ 완료: 명칭 확정·문서 반영 / ⏳ 대기: 게임 표시·대사 적용·검수.** 기존 에셋 경로·내부 ID·저장 키는 유지한다.

## 개인 마을·공용 만남 광장 — 2026-10-20 사용자 채택

**P1 (Major) · ✅ 완료: 기획 반영 / ⏳ 대기: 상세 설계·구현·게임 검수.** 한 마을에 여러 유저의 모습을 함께 표시하려던 방향을 변경하고 생활과 실시간 만남의 공간을 분리한다.

| 공간 | 역할·이용 범위 |
| :--- | :--- |
| 개인 마을 | 플레이어 자신의 집·집꾸미기·NPC 교류·가게 주문 노동·투자 등 생활과 진행의 공간. 다른 유저는 주인의 초대를 수락해 방문하며, 방문 중에는 서로의 모습이 보인다. 방문자가 없을 때는 자신의 생활 공간으로 이용한다. 기존 핵심 시설과 우체국·집 앞 우편함 기획을 유지한다. |
| 공용 만남 광장 | 여러 유저의 모습이 함께 보이며 대화와 교류를 하는 별도 공간. 만나고 싶을 때 선택해서 방문한다. |

- 마을 안의 **광장 쉼터**는 나무·벤치·주민 게시판이 있는 개인 마을의 장소다. NPC 주민의 모임·부탁과 안나의 벤치 재회는 이곳에 유지하며 공용 만남 광장으로 옮기지 않는다.
- 기본 이동 흐름은 개인 마을 → 공용 만남 광장 → 개인 마을 복귀다. 출구·메뉴 등 이동 UI와 정확한 진입·복귀 지점은 후속 설계한다. 정류장의 반복 승차·요금 시스템을 확정하는 뜻은 아니다.
- 정착·노동·투자·회복 등 필수 진행은 개인 마을에서 가능하게 두며 만남 광장 입장을 요구하지 않는다. 개인 공간이라는 구분은 오프라인 전용이나 서버 기능 제거를 뜻하지 않는다.
- 채널 선택이 필요하다면 공용 만남 광장 입장에 연결한다. 기존 온라인 타운 입장·채널 선택 설명은 개인 마을의 입장 조건으로 사용하지 않는다.
- **2026-10-20 초대 방문 후속 채택:** 개인 마을은 유저끼리 초대하고 방문하는 방식으로 운영한다. 주인의 초대 → 상대 수락 → 마을 방문 → 자신의 마을 복귀를 기본 흐름으로 두며 [방문 정책](MOD_GDD_09_FriendSystem.md)을 따른다. 초대 UI·대상 조건·인원·주인 접속 조건·집 실내 및 시설 이용 권한은 후속 설계한다.
- 광장 수용 인원·채널 구성·매칭·동기화 범위·대화 방식·개방 시점은 미정이다. 기존 저장·에셋을 자동 변경하지 않으며 문서 반영과 게임 전환 완료를 구분한다.

소셜 기능은 [친구 시스템](MOD_GDD_09_FriendSystem.md), 도입 연결은 [튜토리얼](CORE_GDD_10_TutorialSystem.md)을 따른다.

### 도시 광장·오락실·카페·이벤트 야시장 — 2026-10-20 후속 사용자 채택

**P1 (Major) · ✅ 완료: 시설·운영 방향 기획 반영 / ⏳ 대기: 상세 콘텐츠·배치·제작·구현·게임 검수.** 공용 만남 광장은 도시적인 분위기로 구성하고 큰 전광판을 배치한다. 오락실과 카페를 상시 시설로 추가하며, 이벤트 기간에는 임시 부스를 차려 야시장 같은 분위기를 만든다. 상시 시설이라는 구분은 24시간 영업이나 초기 출시 시점 확정을 뜻하지 않는다.

- 평상시에는 오락실에서 놀고 카페에서 머물며 다른 유저와 만나는 흐름을 만든다. 구체 게임·메뉴·이용 조건은 [생활과 사교](MOD_GDD_05_LifestyleSocial.md)에서 후속 설계한다.
- 이벤트 때 부스를 놓을 여유 공간을 확보하되 소망 나무 주변의 모임 공간·시설 출입구·버스 정류장 귀환 동선은 유지한다. 정확한 부스 위치·개수·배치도는 미정이다.
- 야시장은 이벤트 운영 방향이다. 매일 밤 열리는 상설 시장이나 유저가 직접 판매하는 벼룩시장을 확정하지 않는다. 개최 기간·시간 기준·NPC/유저 운영 여부·상품·미니게임·이벤트 재화·보상은 후속 설계한다.
- 대형 전광판의 표시 내용은 미정이며 모의투자룸 내부의 시즌 랭킹 전광판을 광장으로 자동 이전하거나 동일 기능으로 확정하지 않는다. 사진 명소의 꽃 아치·도시 조형물 제안도 아직 미채택이다.
- 개인 마을의 생활·필수 진행과 광장 초대 방문 원칙은 유지한다. 기존 펍·잡화점·금융 시설의 기능이나 경제 수치를 새 시설에 자동 승계하지 않는다.

**2026-10-20 옵시디언 후속 채택:** 옵시디언은 **공용 만남 광장의 사이퍼 증권 본점 전용 기능**으로 둔다. 개인 마을 증권사에는 옵시디언 가입/이용 기능을 제공하지 않는다. 가입 조건·혜택·세부 기능·공간 연결과 그 외 본점 역할은 [금융 시설 명세](CORE_GDD_04_FinancialInstitutions.md)에서 후속 설계한다. 개인 마을의 투자 입문·기본 거래·필수 진행은 유지한다. **P1 (Major) · ✅ 기획 반영 / ⏳ 상세 설계·구현·검수 대기.**

**2026-10-20 증권사 본점 추가 채택:** 공용 만남 광장에 **사이퍼 증권 본점**을 추가한다. 앞서 정한 네 요소만으로 구성을 제한하지 않는다. 개인 마을의 사이퍼 증권은 유지하고 투자 자격증·거래 기초·첫 매수 등 필수 진행을 공용 광장으로 이전하지 않는다. 본점의 구체 기능·배치·개방 조건은 후속 설계하며, 기존 아레나·상금 배틀·공개 매매 확장안을 본점의 확정 기능으로 승계하지 않는다. ## 2. 완성형 홈 오피스 및 일반 실내

홈 오피스와 일반 건물 내부는 아이소메트릭의 **고정 배치 완성형 룸**으로 제작합니다. 홈은 테마 룸 단위로 구매·선택하고, 일반 시설은 운영용 패키지로 구성합니다. 일반 시설 룸을 판매 상품으로 자동 분류하지 않습니다.

- **편집 방식:** 가구 단품 자유 배치·회전과 벽지/바닥 개별 조합을 테마 룸 선택으로 대체합니다. 일부 소품 슬롯은 후속 후보입니다.
- **기능 유지:** 책상 거래, 의자·벤치 휴식, 침대 눕기, 옷장과 시설 이용, 출입구 이동을 고정 상호작용 지점으로 제공합니다.
- **제작 단위:** 바닥·벽·고정 가구·장식을 통합하고 캐릭터 가림·동작·HTML/CSS 표시가 필요한 부분만 분리합니다.
- **논리 공간:** 기존 8×8은 홈 구현 기준입니다. 유저 배치 편집기와 분리하여 이동·충돌·접근 지점 계산에 그리드를 사용할 수 있습니다. 모든 시설 크기를 8×8로 강제하지 않습니다.
- **크기·투영:** 아트 가이드의 실내 공통 셀 규격과 H=90 기준을 이어받고 제안값과 현재 구현값을 구분합니다.
- **출입:** RPG식 탑다운 마을과 아이소메트릭 실내를 문으로 연결하고 진입·복귀 위치와 상대 크기를 검증합니다.

상세 레이어·좌표·입력·상호작용·룸 교체 계약은 [완성형 룸 명세](ROOM_PACKAGE_GUIDE.md), 판매는 [Modern Frame](MOD_GDD_03_2_JulianFurniture.md)을 따릅니다. 기존 가구·배치·버프·매각·압류 데이터는 정책과 마이그레이션 없이 삭제하거나 룸으로 자동 환산하지 않습니다.
