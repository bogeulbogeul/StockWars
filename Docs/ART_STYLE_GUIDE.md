# StockWars 아트 스타일 가이드

> **최종 개정:** 2026-10-05 — 건물 내부 공통 그리드 통합 및 가구 설계용 캐릭터 기준 키 기록
> **상태:** 장소별 시점 방향 결정 / 실내외 연결 검증 예정 / 2D 리깅 제작 방식 확정 / 최종 화풍·캐릭터 제작 착수 보류

## 1. 현재 결정

**마을은 RPG식 탑다운, 홈 오피스와 일반 건물 내부는 아이소메트릭**으로 구성한다. 마을은 길 찾기와 시설 접근성을, 실내는 가구의 입체감과 공간을 꾸미는 재미를 강조한다. 이전의 전 공간 탑다운 통일 방침을 대체한다. 임시 에셋으로 공간과 이동부터 검증하고 캐릭터 외형과 최종 화풍은 이후 결정한다. 캐릭터는 파츠를 분리하고 본을 심는 2D 리깅 방식으로 제작한다.

픽셀아트는 필수 조건이 아니다. 기존의 '코지 SD 픽셀아트 확정', 1px 외곽선, 3단계 명암, 픽셀 밀도 고정 규칙은 현행 필수 기준에서 해제한다. 깔끔함과 가독성을 우선하되 최종 그림체·도구를 이번 결정으로 확정하지 않는다. 캐릭터의 제작 방식은 파츠 분리와 본 기반 2D 리깅으로 정한다.

- **마을 시점:** 건물 정면과 지붕이 함께 보이는 RPG식 탑다운이다. 수직으로 내려다보는 시점이 아니며 길과 이동 동선은 화면 가로·세로를 중심으로 구성한다.
- **실내 시점·공간 축:** 홈 오피스와 일반 건물 내부는 바닥의 두 축이 화면 대각선으로 보이는 아이소메트릭으로 구성한다. 한 칸의 크기와 각도는 실내 공통 규격으로 통일한다. 아래 공통 규격 제안의 수치는 검증 후 확정하며, 논리 그리드와 화면 표현을 구분한다.
- **이동·크기:** 화면 방향에 대응하는 이동 입력을 검증 시작안으로 삼는다. 실내 바닥 축 때문에 조작 방향이 혼동되지 않는지 확인하고 실내외 상대 크기와 카메라 배율을 조율한다. 동일 캐릭터 그림·리그의 두 시점 호환을 보장하지 않으며 추가 방향별 그림·모션의 필요 여부는 검증한다.
- **가독성:** 이동 가능한 바닥, 출입구, 상호작용 대상과 거래 UI의 숫자·글자·차트가 명확히 구분되어야 한다.

마을 동선은 가로로 길어도 되지만 횡스크롤 전용 시점을 사용하지 않는다. 비트 물류 등 별도 미니게임의 시점·물리·조작 변경은 별도 검토한다.

### 건물 내부 공통 그리드

홈오피스와 일반 건물 내부의 바닥·가구·이동에 사용하는 그리드 기준을 정리한다. **모든 실내에서 한 칸의 크기와 투영 각도를 일정하게 유지한다.** 건물의 면적은 칸 수로 조절한다.

한 칸의 규격을 통일하는 것은 사용자 요청에 따른 기준이다. 아래 수치는 현재 홈오피스 좌표계를 바탕으로 한 **공통 규격 제안**이며, 모든 실내 코드와 에셋에 적용 완료된 값은 아니다. 최종 공통 수치와 기존 룸의 전환은 후속 검증에서 확정한다.

#### 공통 한 칸 규격

논리 공간의 한 칸은 1×1 정사각형이다. 화면에서는 원근에 따른 크기 변화가 없는 마름모로 투영한다. 가까운 칸과 먼 칸, 방 중앙과 가장자리의 칸은 동일한 크기다.

| 항목 | 공통 규격 제안 |
| :--- | :--- |
| 한 칸의 논리 크기 | 1×1 |
| 한 칸의 화면 가로 대각선 | 67.5 기준 단위 |
| 한 칸의 화면 세로 대각선 | 38.2 기준 단위 |
| 반폭과 반높이 | 33.75 / 19.1 기준 단위 |
| 그리드 선 각도 | 화면 수평 기준 ±29.50664658° |
| 기울기 절댓값 | 19.1 / 33.75 ≈ 0.5659259259 |

기준 단위는 현재 홈오피스 SVG 좌표 단위다. 원본 이미지의 픽셀 수나 실제 길이 단위와 동일하다고 가정하지 않는다. 화면 확대·축소 시에는 룸·가구·그리드에 같은 균일 배율을 적용한다. 건물마다 한 칸의 기준 크기를 바꾸어 면적을 맞추지 않는다.

#### 각도의 읽는 방법

각도는 화면의 가로선을 기준으로 잰다. 화면 좌표는 오른쪽이 +X, 아래쪽이 +Y다. 아래의 ± 표기는 두 그리드 선의 기울기를 뜻하며, 축의 증가 방향까지 나타내려면 벡터를 함께 사용한다.

| 논리 축 | 한 칸 증가 시 화면 이동 | 증가 방향의 각도 |
| :--- | :--- | :--- |
| gx | 왼쪽 33.75, 아래 19.1 | 오른쪽 수평에서 화면 시계 방향으로 150.49335342° |
| gy | 오른쪽 33.75, 아래 19.1 | 오른쪽 수평에서 화면 시계 방향으로 29.50664658° |

두 선은 화면에서 수평 기준 약 29.51°로 기울어진다. 이 값은 바닥 격자 선의 각도이며 카메라의 내려다보는 각도를 직접 지정하는 값은 아니다. 현재 프로젝트에서 사용하는 아이소메트릭 실내 표현의 제작 기준이며, 엄밀한 등각 투영의 30°로 임의 반올림하여 에셋을 제작하지 않는다.

원점 `(Ox, Oy)`에서 격자 교차점의 위치는 다음과 같다.

```text
screenX = Ox + (gy - gx) × 33.75
screenY = Oy + (gx + gy) × 19.1
```

원점은 룸마다 달라도 된다. 한 칸의 크기와 축 벡터는 공통으로 유지한다. 셀 `(gx, gy)`의 중심은 위 식에 `(gx + 0.5, gy + 0.5)`를 넣어 구한다.

#### 건물 면적과 배치

8×8과 10×10은 방의 전체 칸 수다. 한 칸의 규격이 같다면 10×10 방이 8×8 방보다 넓다. 모든 건물을 8×8로 제한하지 않으며 건물 용도에 맞춰 가로·세로 칸 수를 정한다.

- 가구의 점유 크기는 1×1, 1×2, 2×3처럼 논리 칸 수로 기록한다. 그림의 높이와 투명 여백은 바닥 점유 면적에 포함하지 않는다.
- 문·계단·직원 자리·상호작용 지점과 이동 통로는 점유 칸과 함께 기록하고, 출입구에서 목적지까지 이동 가능한지 확인한다.

#### 현재 구현과 전환 범위

현재 룸별 한 칸 수치는 서로 다르다. 아래는 코드에서 확인한 기존 값이며 공통 규격을 이미 적용했다는 뜻은 아니다.

| 룸 | 현재 전체 칸 수 | 현재 한 칸의 화면 대각선 | 기준 코드 |
| :--- | :--- | :--- | :--- |
| 홈오피스 | 8×8 | 67.5×38.2 | [OfficeGrid.js](../web/js/components/office/OfficeGrid.js) |
| 비비안 잡화점 | 8×8 | 170×82 | [IsometricRoomGrid.js](../web/js/components/store/IsometricRoomGrid.js) |
| 증권사 | 10×10 | 131.2×67 | [CipherGrid.js](../web/js/components/CipherGrid.js) |

각 값은 해당 룸의 로컬 좌표 단위다. 숫자만으로 현재 화면에서의 실제 픽셀 크기를 비교할 수는 없다. 홈오피스 수치를 공통 기준으로 제안한 이유는 현재 좌표계와 가구 배치 기준이 기록되어 있기 때문이다.

공통 규격으로 전환할 때에는 원본 룸 바닥과 가구의 각도부터 확인한다. 디버그 선만 교체해서 기존 바닥과 어긋나게 만들지 않는다. 임시 에셋으로 줄눈 일치, 접지점, 점유 영역, 이동·충돌·가림과 마을 왕복을 검증한 뒤 적용한다.

### 캐릭터 기준 크기와 가구 치수

사용자 요청(2026-10-05)에 따라 **가구 설계용 기본 캐릭터 기준 키는 H = 90 기준 단위**로 정한다. 현재 홈오피스에 기록된 안나의 표시 키 `90 SVG 단위`를 기준으로 삼는다. 이는 공간·가구의 상대 크기를 맞추기 위한 기준이며, 최종 캐릭터 외형·머리와 몸의 비율·원본 해상도를 확정하는 결정은 아니다.

| 항목 | 기준 |
| :--- | :--- |
| 기본 캐릭터의 서 있는 키 | H = 90 기준 단위 |
| 키 측정 구간 | 기본 신발을 착용한 중립 직립 자세의 발바닥 접지선부터 머리 꼭대기까지 |
| 측정 제외 영역 | 투명 여백, 그림자, 모자·솟은 헤어·장식, 닉네임·상호작용 UI |
| 발밑 배치 기준점 | 양발 사이의 바닥 기준점. 이동·가구 정렬에 공통으로 사용 |
| 공통 그리드 제안과의 화면 비율 | H / 한 칸 가로 대각선 = 90 / 67.5 ≈ 1.3333 |

기준 키는 확대·축소 전 룸 좌표의 화면 세로 길이다. 카메라 배율이 `s`이면 캐릭터 키는 `90 × s`, 타일 대각선은 `67.5 × s`와 `38.2 × s`로 표시한다. 캐릭터만 별도 배율로 키워 가구와의 비율을 바꾸지 않는다. 위 비율은 투영된 화면 길이의 비교이며 캐릭터가 바닥에서 1.3333칸을 차지한다는 뜻은 아니다.

같은 기본 체형의 스타일은 장식·투명 여백이 달라도 기준 키와 접지점을 유지한다. 이미지 전체 높이를 90으로 맞추는 대신 측정 구간에 균일 배율을 적용한다. 캐릭터 폭·체형별 키 차이·충돌 영역은 후속 검증에서 정하며, 그림의 바운딩 박스를 충돌 영역으로 자동 사용하지 않는다. 마을에서는 실내외 왕복 시 상대 크기를 검증하고 해당 좌표계에 환산한다. 모든 장소에서 원시 코드값 90을 그대로 쓰는 규칙은 아니다.

#### 가구 높이 검증 시작값

다음은 H를 기준으로 한 **설계 제안**이며 기존 가구 이미지의 실측값이나 최종 확정 치수가 아니다. 높이는 바닥 접지선에서 해당 표면까지 화면 수직 방향으로 잰다. 바닥 가로·세로 크기는 별도로 점유 칸 수로 기록한다.

| 가구 표면 | 기준 키에 대한 비율 | H = 90일 때 높이 |
| :--- | :--- | :--- |
| 의자 좌석 | 0.40H | 36 기준 단위 |
| 책상 상판 | 0.60H | 54 기준 단위 |
| 침대 매트리스 윗면 | 0.35H | 31.5 기준 단위 |
| 옷장 상단 | 1.20H | 108 기준 단위 |

캐릭터와 가구를 같은 룸에서 비교하고 책상 앞 서기·의자 앉기·침대 눕기의 접지와 손·발·좌석 위치를 검증한다. 최종 체형과 생활 모션이 정해지면 위 시작값을 조율한다. 원본 PNG의 투명 여백을 포함한 이미지 높이로 가구 높이를 대신하지 않으며, 검증되지 않은 앉은 키나 팔다리 길이를 확정값으로 추가하지 않는다.

### 건물 내부 에셋은 그리드 기준으로 제작

사용자 지시(2026-10-04)에 따라 **앞으로 실내 룸 형태는 현재 비비안 잡화점을 기준으로 한다.** 뒤쪽 두 벽과 마름모꼴 바닥이 자연스럽게 이어지는 열린 아이소메트릭 구조를 사용하며, 벽·바닥·외곽 테두리는 하나의 통합 룸 에셋으로 제작한다. 바닥 모서리와 끝 기둥의 접지 위치를 처음부터 일치시킨다. 건물별 색상·문·계단·면적은 용도에 따라 달리할 수 있으며 비비안의 8×8 크기를 모든 건물에 강제하지 않는다. 가구·NPC·장식은 통합 룸과 별도로 제작한다.

가구 배치에는 타일 줄눈과 같은 좌표 기준을 사용한다. 디버그 그리드만 별도로 눈대중 조절하지 않고, 표시·가구 기준점·점유 칸·입력 좌표 변환이 공유할 룸 좌표 모듈을 둔다. 새 룸은 균일한 정사영 타일을 기준으로 제작하고 실제 줄눈 교차점과 배치 좌표를 검증한다. 기존 생성 이미지에 남은 불균일한 줄눈을 보정하는 것은 해당 에셋의 임시 대응이며, 원근이나 비균일 타일을 향후 제작 기준으로 채택하는 뜻이 아니다.

현재 증권사 통합 룸은 `web/assets/interiors/cipher/cipher-room-unified-10x10-v2.svg`이다. 기존 벽·문·계단 그림과 정확히 100개의 균일한 바닥 타일을 통합했다. `web/js/components/CipherGrid.js`의 `cipherGridToScreen`을 룸 제작·디버그 표시·가구 배치에 함께 사용한다. 10×10 전체 칸과 마지막 외곽 줄을 배치 범위로 인정하며, 계단·문 통로와 가구 충돌 제한은 별도로 유지한다. 화면의 마름모는 바닥 정사각형의 아이소메트릭 투영이다.

사용자 지시(2026-09-29)에 따라 **건물 내부 룸은 아이소메트릭 형태로 제작하며 그리드를 적용한다. 가구는 해당 룸의 그리드 축과 평행하도록 제작한다.** 앞으로 룸·가구·장식 이미지는 실제 적용할 아이소메트릭 그리드를 먼저 확인하고 그 기준에 맞춰 생성한다.

여기서 가구와 그리드의 ‘수평을 맞춘다’는 것은 화면의 가로 방향으로 눕힌다는 뜻이 아니라, **가구의 윗면과 아랫면을 포함한 각 수평 모서리가 바닥 그리드의 대응하는 대각선 축과 평행해야 한다**는 뜻이다. 이 조건은 생성 원본부터 충족해야 하며, 게임에 적용한 모습에서도 유지되어야 한다.

- 생성 전에 해당 룸의 그리드 원점, 두 축, 한 칸의 화면 크기와 에셋의 점유 칸 수(예: 1×1, 1×2, 2×2)를 정한다. 현재 비비안 룸의 기준은 `web/js/components/store/IsometricRoomGrid.js`의 `ROOM_GRID`이며, 생성할 때 최신 코드를 확인한다. 현재 8×8 설정과 투영 수치는 비비안 룸의 적용 기준이며 모든 건물의 크기나 최종 투영 수치를 고정하는 뜻은 아니다.
- 룸 바닥의 타일 경계와 논리 그리드 선이 일치하도록 생성한다. 가구·카펫은 바닥 접지면이 지정된 칸 안에 들어가도록 하고, 높이로 인해 위쪽으로 보이는 영역과 실제 바닥 점유 영역을 구분한다.
- 가구의 방향, 발밑 배치 기준점, 점유 칸, 직원 자리와 상호작용·출입 통로를 생성 프롬프트에 명시한다. 벽 시계·벽 선반은 벽면 축과 설치 높이를 함께 맞춘다.
- 룸과 가구·장식은 분리 제작한다. 분리 에셋은 투명 배경을 사용하고, 룸과 같은 시점·선명한 윤곽선·깔끔한 색면을 유지한다. 바닥은 규칙적인 타일과 균일한 줄눈으로 그리며 번진 수채화 질감이나 얼룩을 피한다.
- 생성 후 실제 룸의 그리드 위에 올려 접지면, 방향, 크기, 겹침과 출입 동선을 확인한다. 그리드에 맞지 않는 결과는 적용 완료로 간주하지 않는다. 이후 수정도 동일한 그리드 기준을 유지한다.
- 가구의 밑면만으로 각도를 검증하지 않는다. 상단 프레임·윗판·중간 선반·밑판의 같은 방향 모서리가 서로 평행하고 실제 그리드 축과 일치하는지 각각 확인한다. 높이에 따라 기울기가 달라지는 원근 표현은 정사영 실내 가구에 사용하지 않는다.
- 전광판·벽걸이 가구도 같은 기준을 적용한다. 코너형은 왼쪽 상단·하단 선이 왼쪽 그리드 축과, 오른쪽 상단·하단 선이 오른쪽 그리드 축과 각각 평행해야 한다. 프레임 외곽과 화면 안쪽 테두리를 모두 검증하며, 하단만 맞거나 위아래가 벌어지는 에셋은 다시 제작한다. 사용자 재확인: 2026-10-04.
- 적용 시 가로·세로 비율을 유지하여 크기를 조절한다. 그리드에 맞추려고 세로 압축이나 기울이기 변형으로 가구의 형태를 바꾸지 않는다. 원본의 각도가 맞지 않으면 제작 단계에서 수정하고, 원본과 게임 표시를 비교하여 형태가 유지되는지 확인한다.

### 홈오피스 현재 가구 배치 기준

현재 `BasicRoom.png` 홈오피스는 위 공통 규격 제안의 기반인 `web/js/components/office/OfficeGrid.js`를 사용한다. 아래는 홈오피스에 현재 적용된 배치값이며 다른 룸에는 자동 적용하지 않는다.

- SVG 좌표 원점은 `(500,320)`이다. 한 칸 크기·각도·전체 칸 수는 위 표를 따른다.
- 기본 가구는 정수 칸에 배치하고 앞쪽 발끝 기준점을 점유 영역의 앞 꼭짓점에서 두 축 각각 `0.08칸` 안쪽에 둔다. PNG 투명 여백 끝을 접지점으로 사용하지 않는다. 개별 이미지의 접지점과 균일 배율은 가구 데이터에 기록한다.
- 책상 `gx=1,gy=0 / 2×3`, 의자 `3,1 / 1×1`, 옷장 `0,5 / 1×2`, 침대 `4,3 / 2×4`를 현재 기본 배치로 사용한다. `gx×gy` 순서이며 제작 프롬프트의 길이×폭 표기와 구분한다. 중앙 및 문 앞 칸을 비워 둔다.
- 사용자 수정 요청에 따라 이번 변경은 원본 PNG의 형태·각도 재제작을 중단하고 표시 색감과 크기만 조정했다. 안나의 현재 표시 키 `90 SVG 단위`를 기준으로 책상 배율 `0.125`, 의자 `0.086`, 침대 `0.16`, 옷장 `0.108`을 사용한다. 내추럴 우드 테마에 공통 표시 보정 `saturate(0.82) brightness(1.03)`을 게임 및 편집 목록에 동일하게 적용한다. 이 보정은 원본 파일의 색을 변경하지 않는다.
- 침대는 원본의 가파른 긴 프레임을 수정한 `web/assets/office/basic-furniture-v2/bed-grid-v3.png`를 사용한다. 기본 가구는 종횡비를 유지하며 좌우 반전으로 두 방향을 전환한다. 방향 전환 시 점유 가로·세로와 접지점을 함께 변경한다. 이는 뒷면을 표현하는 4방향 회전이 아니며, 4방향은 방향별 추가 이미지 제작 후 지원한다.

게임의 편집 화면에서 그리드·접지·점유 영역을 비교 확인했다. **공통 한 칸 규격에 적힌 각도는 현재 홈오피스 좌표계의 정확한 제작 목표값이다. 생성 PNG의 모든 선이 이 값에 수학적으로 일치한다는 뜻은 아니다.** 생성 원본에 남은 미세한 모서리 각도 차이와 주변 반투명 광택은 후속 제작 검증 대상이며 최종 에셋 채택과 구분한다. PNG를 비균일 변형해 오차를 숨기지 않는다.

## 3. 보류 항목과 기존 자료

최종 화풍, 캐릭터 외형·비율, 해상도, 팔레트, 외곽선, 명암 단계, 모션 길이·키 포즈·속도, 리깅 도구와 런타임 전달 방식은 후속 결정이다.

[기존 픽셀 캐릭터 참고](References/player-compact-pixel-style-reference.png)는 이전 화풍 검토 이력이며 현행 최종 화풍 기준이 아니다. 회색 마네킹·걷기 시트·웹 모션 테스트도 실험 자료로 보존하고 최종 에셋으로 자동 채택하지 않는다. 동작 참고 이미지는 손발 위치·방향·겹침 참고용이며 외형·색감 기준으로 전용하지 않는다.

[제작용 파츠 분리 참고](References/character-parts-rigging-reference.jpg)는 부위 분리 구조의 참고이며 최종 외형·색감 채택이나 참고 게임의 실제 구현을 단정하는 자료가 아니다.

완성형 스타일 선택·판매, 얼굴 독립 선택 제외, 공통 모션과 한정판 특별 모션의 기능 요구는 유지한다. 캐릭터 제작 보류는 파츠 커스터마이징 재도입이나 기능 삭제를 뜻하지 않는다. [캐릭터 제작 가이드](part_separation_guide_512.md)를 따른다.

## 4. 이미지 생성·편집 전 필수 절차

1. 새 이미지 작업마다 이 문서의 최신 내용을 읽는다. 작업 중 개정되면 다음 생성 전에 다시 읽는다.
2. 캐릭터 작업은 [캐릭터 제작 가이드](part_separation_guide_512.md)도 읽고 해당 작업에 지정된 참고 이미지를 열어 확인한 뒤 생성 도구에 전달한다.
3. 참고마다 외형·시점·동작 용도를 구분한다. 과거 픽셀 화풍을 확정 규칙처럼 적용하지 않는다.
4. 장소별 시점·깔끔함·가독성과 사용자 요청을 반영한다. 미정인 화풍·수치를 확정된 것처럼 적지 않고 임시 표현은 검증용 선택으로 기록한다.
5. 실제 표시 크기로 확인하고 생성 시안·검증 완료·최종 채택을 구분한다. 필수 가이드나 참고가 누락되면 알리고 기억으로 대체하지 않는다.

사용자의 명시적 요청을 우선한다. 일회성 실험으로 최종 화풍·제작 방식을 자동 확정하지 않는다. 문서 작성 요청을 이미지 생성 요청으로 해석하지 않는다.
