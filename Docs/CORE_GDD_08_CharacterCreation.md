# StockWars GDD: CORE_GDD_08. 캐릭터 생성 시스템 (Character Creation)

## 2026-10-25 최신 채택 — 분석력·찌라시 10단계

**P1 (Major) · ✅ 완료: 기획 문서 반영 / ⏳ 대기: 원고·데이터·게임 구현·저장 이관·검수.** 분석력은 **Lv.1~10**, 찌라시 해석은 **1~10단계**로 줄인다. 기존 20단계 기획과 아래 과거 표기보다 이번 채택을 우선한다. **1~3단계 수수께끼 → 4~6단계 사건·핵심 조건 → 7~10단계 출처·경쟁·시점·정보의 한계**로 이어지며, [작성 원칙과 10단계 예시](RUMOR_AUTHORING_GUIDE.md)를 따른다. 최대 해석도 진위·수익을 보장하지 않는다.

별가루는 지정 한 건 +1(최대 10)·500잎, 달가루는 지정 한 건 10단계·2,000잎이다. 플레이어 분석력 자체와 다른 찌라시는 바꾸지 않는다. 읽기 후 표시된 내용으로 푸는 퀴즈 성장·가루 사용 여부에 따른 보상 차등 없음은 유지한다. 시작 테스트의 Lv.1~3 배점과 캐릭터 레벨 상한 Lv.20도 유지한다. 현재 게임 해석 상한은 5단계이며 기존 저장·본문을 자동 환산하지 않는다. 성장 속도·숙련도 요구량·이관은 후속 설계한다. 아래 날짜별 기록의 수치는 이 최신 채택 기준으로 갱신하거나 과거 이력으로 구분한다.

## 시작 분석력 테스트 — 2026-10-22 후속 기획

**P1 (Major) · ✅ 완료: 기획·3문항·배점 채택 / ⏳ 대기: UI·저장 이관·구현·검수.** 능력치를 분석력 하나로 정리함에 따라 시작 테스트는 **분석력의 출발 단계를 정하는 정보 해석 테스트**로 바꾼다. 아래 4종 성향 진단·스탯 +1·부가 혜택 유지 설명보다 이번 결정을 우선한다. 기존 주식 하락 시 행동 같은 취향 응답을 정답/오답으로 간주하지 않는다.

주민 신청과 투자 자격증 절차를 분리한 동선은 유지하며 테스트는 사이퍼 증권의 자격증 과정에 둔다. 캐릭터는 Lv.1로 시작하고 분석력만 테스트 결과를 사용한다. 계좌 신청 테스트는 코지페이·리프에너지·이음네트웍스를 사용하는 4지선다 3문항으로 확정한다. 정답 0~1개는 분석력 Lv.1, 2개는 Lv.2, 3개 모두 정답이면 Lv.3으로 시작하며 결과와 관계없이 계좌를 개설한다. 최초 제출 결과를 적용하고 이후에는 플레이 중 퀴즈로 성장한다. [채택 문항·정답·해설](MOD_GDD_18_QuizSystem.md)을 따른다. 신규 불합격·발급 비용은 추가하지 않는다. 기존 저장의 강제 재시험·성향/포인트 환산·중복 초기화는 이관 설계 없이 적용하지 않는다. [성장 개편](CORE_GDD_03_PlayerGrowth.md)을 따른다.

## 최신 등록 방향 — 2026-10-19 후속 채택

**최신 방문 순서 정정:** 정착 안내소가 마을 도착 후 처음 방문하는 건물이다. 안나와 정류장에서 만난 뒤 바로 안내소에서 **마을 입주 신청서**를 작성하고 서명칸에 이름을 입력한다. 마을 안내·빈 집 확인은 신청 후 진행한다. 아래 ‘마을·집을 먼저 둘러본 뒤 신청’ 설명을 대체하며 투자 TPT·자격증은 이후 증권사 절차로 분리한다. ✅ 기획 반영 / ⏳ 구현·검수 대기.

### 주민 신청서 서명으로 이름 등록 — 2026-10-19 후속 채택

**P0 (Core) · ✅ 완료: 기획 반영 / ⏳ 대기: 신청서 UI·저장 연결·검수.** 주민 신청서 하단의 **‘신청인 서명’** 칸에 플레이어가 사용할 이름을 텍스트로 입력한다. 이 값이 기존 닉네임이며 별도 이름 입력 화면이나 중복 서명 입력을 두지 않는다. 기존 닉네임 최대 10글자와 유효성 검사 규칙을 유지한다. 실명 입력이나 손글씨 그리기를 요구하지 않는다.

안나: “당신의 이름을 적어주세요.” → 플레이어 이름 입력 → ‘신청서 제출’로 확인 → 안나: “[닉네임]님, 마을에 오신 걸 환영해요.” 이후 대화 호칭과 투자 자격증에는 같은 이름을 사용한다. ‘태어난 소망’은 비워둘 수 있는 서사 표현으로 유지하며 서명칸과 구별한다. 등록 완료 전에는 입력값을 수정할 수 있고, 이어하기에서 서명을 다시 요구하거나 기존 닉네임을 덮어쓰지 않는다.

**같은 날 최신 선택 분기:** 주민 신청과 투자 자격증 발급을 분리한다. 안내소에서는 고정 요정 미리보기·닉네임·주민 신청을 진행하고 생활 자금 상담·은행·입주로 연결한다. 이후 ‘주식 투자하기’를 선택하면 사이퍼 증권에서 자격증 만들기부터 시작한다. 기존 TPT 3문항·트레이더 출입증 연출은 이 절차로 옮겨 활용하는 설계이며 보너스 지급 시점·발급 전 능력치·저장 이관은 후속 설계한다. 새 시험·합격 점수·비용은 확정하지 않는다. ‘주민 부탁 들어주기’를 먼저 고르면 자격증을 노동 선행 조건으로 두지 않는다. 아래 주민 신청 단계의 TPT·출입증 설명보다 우선한다. [분기 상세](CORE_GDD_10_TutorialSystem.md). ✅ 기획 반영 / ⏳ 구현·검수 대기.

**P0 (Core) · ✅ 완료: 기획 반영 / ⏳ 대기: 화면·진행·저장 이관·검수.** 광고 전단지를 보고 이주한 소망이는 안나와 마을·지낼 집을 먼저 둘러본 뒤 정착 안내소에서 주민 신청서를 작성한다. 신청서에 기존 닉네임 입력을 통합하고 ‘태어난 소망’은 비워둘 수 있는 서사 표현으로 둔다. 고정 외형 미리보기·TPT 3문항·기존 성향 보너스·출입증을 유지한다. 이후 생활 자금 상담 → 노드 은행 정착 대출 → 입주·첫날 안내로 연결한다. 아래 도착 직후 등록·출입증 직후 오피스 직행 설명보다 우선한다. 도입 스킵과 대출 계약 확인의 연결은 후속 설계한다. [튜토리얼](CORE_GDD_10_TutorialSystem.md)·[금융](CORE_GDD_04_FinancialInstitutions.md)을 따른다.

외형 제작은 [정령 기본형](SPIRIT_CHARACTER_BASELINE.md), 초반 장면과 편지·씨앗은 [튜토리얼 서사](CORE_GDD_10_TutorialSystem.md)를 따른다. 소망을 주가 예지·직업·고유 투자 능력으로 사용하지 않는다. 사람형 파츠 선택도 신설하지 않는다.

## 1. 시스템 개요 (System Overview)
유저는 게임을 처음 시작할 때 자신의 가상 아바타와 투자 성향을 설정합니다. 이는 코지(Cozy) 감성의 빈티지한 키오스크 UI 형태를 띠며, 완료 시 유저의 정보가 담긴 '트레이더 출입증'이 출력되는 연출과 함께 게임 본편(홈 오피스)으로 진입합니다.

## 2. 캐릭터 커스터마이징 흐름 (UX Flow)

### 2.1. 단계별 설정

1. **기본 스타일 선택:** 완성형 동물 캐릭터 목록에서 스킨 하나를 선택한다. 동물의 종·얼굴·털색·무늬·귀·꼬리·체형이 포함된 전체 외형이다.
2. **미리보기:** 선택한 전체 외형을 확인한다. 피부색·헤어·얼굴·신발 등을 개별 선택하는 단계는 없다.
3. **닉네임 및 성향 설정:** 기존 닉네임 입력과 투자자 성향 테스트를 진행한다.
4. **등록:** 선택한 스타일과 플레이어 정보를 저장하고 출입증을 발급한다.

기존 성별별 골격 선택 단계는 완성형 스타일 선택으로 대체한다. 게임의 별도 성별 데이터가 필요하다면 후속 설계하며, 성별 선택을 파츠 조합 절차로 사용하지 않는다.

### 2.2. 초기 외형 명세

- 기본 외형은 같은 플레이어가 사용할 스타일이며 별도 직업·고유 스킬을 가진 인물이 아니다.
- 피부색 5종 × 헤어 4종 조합과 공통 기본 의상 고정 규칙은 폐기한다. 각 스킨은 동물 자체의 완성 디자인을 갖는다. 옷·헤어가 필수인 사람형 외형으로 해석하지 않는다.
- 현재 기본 외형 참고는 강아지·검은 고양이다. 초기 선택·무료 제공의 최종 수량과 대상은 미정이며 과거 4종 시작안을 확정값으로 사용하지 않는다.
- 이후 옷장에서 외형 전체를 바꿀 수 있다. 외형 교체로 닉네임·투자 성향·성장·자산을 초기화하지 않는다.
- 제작 기준은 [완성형 스타일 가이드](part_separation_guide_512.md), 구매는 [클레어 스타일 상점](MOD_GDD_03_3_ClaireApparel.md)을 따른다.
- 선택창 정면 미리보기와 실제 월드에서 필요한 4방향·동작 에셋의 완료 상태를 구분한다.

## 3. 투자자 성향 테스트 (Trader Personality Test - TPT) [NEW]
유저는 직접 성향을 선택하는 대신, 빈티지 키오스크에서 진행되는 3가지 질문에 답변하여 자신의 초기 투자 성향을 진단받습니다. (답변 결과에 따라 4대 능력치 중 하나에 **+1 블록** 보너스 부여)

### 3.1. 현재 진단과 보상

현재 질문은 주식 하락 시 행동·여윳돈 사용·수익 이후 행동의 3문항이다. 각 문항의 4개 선택지가 분석·협상·운용·회복에 대응한다. 가장 많이 고른 성향을 적용하며 동점이면 코드의 순서(분석→협상→운용→회복) 중 먼저인 항목을 택한다. 랜덤 재추첨이 아니다. 정확한 문장은 [성향 테스트 코드](../web/js/components/character/PersonalityTestStep.js)를 따른다.

| 성향 | 시작 기본 스탯 | 현재 부가 효과 |
| :--- | :--- | :--- |
| 예리한 분석가 | 분석력 +1 | 해석 단계에 반영, 진위 보증 아님 |
| 베테랑 협상가 | 협상력 +1 | 단계 수수료 감면 뒤 추가 30% 할인, 대출 기능 미구현 |
| 공격적 자산가 | 운용력 +1 | 기본 단계 슬롯에 추가 +2칸, 투자금 Cap 없음 |
| 불굴의 트레이더 | 회복력 +1 | 회복력 단계 효과. 자연 회복 속도·노동 골드 가산 아님 |

2026-10-22 시작 칭호를 포함한 기존 칭호 기획을 폐기한다. 시작 성향과 스탯 효과는 유지하며 자세한 계산은 [성장 명세](CORE_GDD_03_PlayerGrowth.md)를 따른다. [폐기 범위·구현 상태](FEATURE_RETIREMENT_2026-10-22.md)를 따른다.

## 4. 연출 및 UX 가이드

### 4.1. 화면 구성
- **중앙**: 아바타 실시간 프리뷰. 현행 동물 캐릭터와 [시트 기준](DOG_SPRITE_BASELINE.md)의 채택 외형을 사용한다. 실내외 시점 연결·UI 적용의 검수 상태는 별도로 확인하며 픽셀 표현을 필수로 요구하지 않는다.
- **하단**: 각 단계별 선택 버튼 및 진행 바.
- **최종**: '트레이더 등록(Register)' 버튼.

### 4.2. 트레이더 출입증 발급 (ID Card Ceremony)
1. 등록 완료 시, 지지직거리는 도트 프린터 효과음 발생.
2. 화면 하단에서 유저의 얼굴, 닉네임, 성향이 인쇄된 **[트레이더 출입증]** 에셋이 슬라이드 업.
3. 안나의 목소리(혹은 텍스트): "환영합니다, [Name] 트레이더님. 당신의 전용 오피스가 준비되었습니다."
4. 출입증을 클릭하면 화면이 화이트 아웃되며 홈 오피스로 전환.

## 5. 데이터 연동 및 무결성
- **초기 자산**: 5,000G 현금. 웰컴 론 10,000G은 미구현 검토안이며 현재 등록 보상으로 합산하지 않는다.
- **스탯 반영**: 선택 성향은 프로필과 아이템 상태의 `baseStats`·`appliedTrait`로 적용하고 현행 로컬 저장에 보존한다. 서버 `User_Stats` DB 저장 완료를 뜻하지 않는다.
