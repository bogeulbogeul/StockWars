## 1. 판매 단위

벽·바닥·가구 배치가 완성된 홈 오피스 테마를 룸 단위로 직접 판매한다. 유저는 보유 룸을 선택하여 적용한다. 개별 가구 구매·이동·90도 회전과 벽지/바닥 단품 조합은 신규 기본 상품·편집 기능에서 대체한다. 가구 기능은 룸에 지정된 상호작용으로 유지한다.

일반 건물 내부도 같은 패키지 방식으로 제작하지만 시설용 룸을 모두 구매 가능한 홈 상품으로 취급하지 않는다. 룸과 내부 레이어는 판매 단위가 다르며 CSS 효과·가림 레이어를 별도 상품으로 쪼개지 않는다.

럭키 캡슐 뽑기와 마일리지 폐기, 직접 구매 정책을 유지한다. 기존 가구 등급·레벨 잠금은 다시 도입하지 않는다. 신규 가격·출시 수량·진열 수량·갱신 주기·할인율은 후속 결정이다. 이전 단품 중심 일일 6~10개 진열 규칙을 룸에 자동 적용하지 않는다.

## 2. 상품과 적용 흐름

**전체 룸 미리보기 → 포함 기능·고정 배치 확인 → 직접 구매 → 보유 룸 선택 → 적용**

- 상품 카드는 전체 외형·포함 기능·가격·보유 상태·적용 상태를 표시한다.
- 기본 홈 룸은 거래·출입·생활에 필요한 기능을 제공한다. 장식 테마 구매를 핵심 기능 접근의 필수 조건으로 만들지 않는다.
- 거래 책상, 의자, 침대, 옷장, 출입구 등 기능을 룸의 고정 지점으로 제공한다. 장식 그림과 실제 이용 가능한 대상을 구분한다.
- 룸 교체 시 새 패키지와 안전 위치를 검증하고 현재 상호작용을 종료한 후 적용한다. 실패 시 기존 룸을 유지한다.
- 보유와 적용은 룸 ID 단위로 저장하는 방향이다. 실제 필드·저장 버전·이관은 구현 전에 정한다.
- 정해진 자리의 소품 교체는 향후 후보이며 자유 배치나 단품 판매를 이번에 다시 추가하지 않는다.

## 3. 테마 후보

내추럴 스타터, 모던 다크, 미니멀 화이트, 네온 사이버, 펜트하우스 등 기존 테마명은 디자인 후보로 활용한다. 최종 룸 목록·가격·보너스는 미정이며 구 단품 가격을 합산하여 룸 가격으로 확정하지 않는다. 새 전용 모션이나 캐릭터 기능도 테마명만으로 추가하지 않는다.

## 4. 기존 기획 및 데이터 전환

이전 단품·로테이션 카탈로그는 폐기했다. 구 단품 목록·가격·규격·효과를 신규 룸 상품 명세로 승계하지 않는다.

기존 보유 가구·배치 데이터·가구 버프·은행 테마 개수 조건·전당포 매각·압류·테마 수집 보상은 연동 정책 검토가 필요하다. 룸 구매로 구 가구 버프를 전부 합산하거나 기존 보유 아이템을 임의 삭제하지 않는다. 소유권 처리·보상·매핑·효과를 정한 뒤 저장 버전과 함께 전환한다. 문서 변경만으로 현재 런타임 경제 규칙을 변경하지 않는다.
