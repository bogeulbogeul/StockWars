# Docs_Collapse — 데모 범위 슬림 문서

## 왜 이 폴더가 필요한가

원본 `Docs/`는 36개 GDD에 약 5,000줄, 로드맵은 350개 항목입니다.
지금처럼 **한 항목씩 AI에 시키는 방식**으로 작업하면, 매번 관련 GDD 전문이 컨텍스트로 올라가서 토큰이 금방 바닥납니다.

이 폴더는 **GIGDC 데모 빌드(튜토리얼 → 캐릭터 Lv.3)에만 필요한 사양**을 모은 슬림 버전입니다.
원본은 데모 제출 후 부활시킬 자료이니 그대로 두세요.

---

## 워크플로우 (중요)

이 폴더의 진짜 목적은 문서 분량을 줄이는 게 아니라 **작업 방식을 바꾸는 것**입니다.

1. **`ROADMAP_DEMO.md`만 보고 작업**하세요. 원본 `ROADMAP_Development_Roadmap.md`는 잠시 잊으세요.
2. **AI 세션 1개당 마일스톤 1개**를 처리하세요.
   - ❌ 나쁨: "로드맵 16번 개발해줘" → 이렇게 350번 반복할 건가요?
   - ✅ 좋음: "M4 마일스톤 전체 구현해줘 (StockDataSO 24종목 일괄)"
3. **마일스톤 1개가 끝나면 새 세션을 시작**하세요. 컨텍스트 누적을 막기 위해서입니다.
4. 마일스톤마다 참조하는 GDD는 **1~2개로 한정**되어 있습니다.
5. **이제부터 🤖[Claude] 태그는 쓰지 마세요.** 슬림 로드맵에는 들어 있지 않습니다.

## 슬리밍 패턴 (스스로 슬림하게 만들 때)

원본 GDD를 슬림 버전으로 줄이는 방법:

### 패턴 A: 반복 데이터 → 표/CSV
- **나쁜 예 (원본 찌라시 라이브러리)**: 24종목 × 6 텍스트를 줄글로 다 풀어 써서 918줄.
- **좋은 예 (슬림)**: 메커니즘 1회 정의 + 종목 3~5개 샘플 + 나머지는 CSV.

### 패턴 B: 데모 외 기능 잘라내기
- `[데모 이후]` 태그가 붙은 모든 항목 → 슬림본에는 한 줄로만 언급.
- 예: "MOD_GDD_15 기관 시스템 → 데모 후."

### 패턴 C: Tier/등급/배율 같은 메커니즘은 1번만 설명
- 종목마다 "Tier 1/2/3은 ~한 의미입니다" 반복 X.
- 문서 상단 한 번이면 충분.

### 패턴 D: 플레이버 텍스트는 짧게
- "코지하고 빈티지한 노란 조명 아래 안나가 부드럽게 미소 짓는 모습이..." 같은 묘사 → 데모 후.
- 데모 구현 단계에서는 "Anna idle 애니" 한 줄이면 됨.

**예시 결과물**: `MOD_GDD_04_RumorLibrary_SLIM.md`를 보세요. 918줄 → 약 120줄.
